Scope: read-only javap of the existing final compileReleaseKotlin classes. No Gradle, installation, device/network I/O, source edits, heap inspection or user-data collection was performed for this review. 1. Bound Android I/O — 01-bound-android-network.javap.txt
AndroidSaveNetworkBackend$bind$1 has one instance field, $network. openConnection(URI) loads it and calls Network.openConnection(URL, Proxy.NO_PROXY). resolve(String) loads the same field and calls Network.getAllByName. createSocket() calls the same field's Network.getSocketFactory().createSocket(). No process-binding or fallback call appears in this class.

2. Release policy injection — 06-release-runtime-injection.javap.txt
AndroidSaveRuntime._init_$lambda$22 passes its networkPolicy field into the SystemHttpsDirectTransfer constructor and AndroidHlsStreamPort constructor. AndroidHlsStreamPort.prepare creates a fresh SystemHttpsHlsFetcher and passes its networkPolicy field to that constructor. The default-argument masks leave the supplied policy intact; they default only the unrelated optional clock/connection arguments. Production Release therefore does not silently choose the permissive policy default.

3. The same request binding reaches I/O and watchdog — 03, 04, 05
SystemHttpsConnectionFactory.open(URI,int,TransferNetworkBinding) calls argument 3's openConnection, and passes that same argument to PublicPeerTlsSocketFactory with the connection's existing TLS factory. Its failure paths close and throw; they do not invoke the unrestricted two-argument overload. PublicPeerTlsSocketFactory.connect calls its stored binding.resolve and binding.createSocket, and still validates Socket.getInetAddress through requirePublic before calling the original TLS delegate. It does not install a new hostname verifier or trust exception.
Direct.transfer acquires a binding inside the redirect loop, stores it in a request local, and passes that same local both to DirectConnectionFactory.open(URI,int,binding) and the synchronous guard-initializer closure. That closure constructs TransferGuard with its captured binding parameter. HLS fetchManifest and fetchSegment do the same using a newly allocated SystemHttpsHlsFetcher$request$guard$2; its invoke() passes the captured $network to HlsTransferGuard. initializeNetworkOwner invokes the initializer synchronously and does not retain it. Neither transport has a cached binding field.

4. Isolation and retained state — 02, 07, 08
SaveWifiNetworkPolicy holds backend and volatile SaveSettings only. It has no source URL, task ID, header, credential or cached-binding field. acquire() allocates a fresh wrapper capturing the policy, selected Network identity and delegate. The unrestricted singleton delegate has no request state; it may be shared when disabled, but the production policy still creates a fresh request wrapper. DirectTransfer and HlsFetcher add only a networkPolicy reference; approved bindings remain local to a request and its initializer/TLS wrapper/watchdog. The initializer helper has no fields. This introduces no shared source/credential storage or cross-request cached approved route.
The pre-existing runtime lease store remains an in-memory map. Its headers() still returns an empty map for an absent reference or non-first hop, rejects expired leases and mismatched exact selected/target identities or origin, and returns a copy of the approved headers. Both transports continue to reject a process-global CookieHandler. HLS lifetime Session remains fetcher-instance state, with prepare allocating a fresh fetcher for each new preparation. No new cross-task source/credential state is introduced.

5. Resource-release fencing — 03, 04, 05, 10
After acquiring a connection/socket, factory/TLS setup failures, including LinkageError, run owned-resource cleanup. Cleanup failures are represented by RECOVERY_REQUIRED or RESOURCE_RELEASE_UNCONFIRMED and retain the transport's recovery fence. initializeNetworkOwner closes a connection if guard initialization fails; failed close invokes its recovery callback before throwing RESOURCE_RELEASE_UNCONFIRMED. Direct.consume's owned output is closed in an unconditional finally path, including when the input getter fails before use(). Input/output close failures and LinkageError are classified without downgrading unreleased resources to a Wi-Fi wait. Explicit cancellation still precedes a previously latched WIFI_REQUIRED when cleanup succeeds.

Conclusion: the final inspected Release bytecode supports request-scoped Android Network pinning, actual runtime injection, preserved TLS/peer checks, release fencing and the absence of newly shared source/credential state. It does not justify an unrestricted global assertion that every application feature is incapable of leaking data; use the bounded findings together with the completed JVM isolation/network tests.

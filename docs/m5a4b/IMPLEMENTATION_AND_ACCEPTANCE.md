# M5-A4b ordinary remembered-folder implementation

## Design

1. The existing application-scoped ordinary-destination runtime owns both the new settings flow and A4a creation admission. Every system picker launch uses a durably consumed, never-reused correlation code and a process-memory ticket through a non-restored result bridge. Neither URI nor ticket becomes authority through saved state. Rotation/detachment, cancellation, duplicate results and delayed callbacks cannot consume a newer request. The current ticket is checked before taking persistent permission and at the final bounded database preference commit.
2. Only returned read/write flags are taken, and only when the persistable flag was actually offered. The Android registry validates canonical tree identity, exact current `persistedUriPermissions`, current URI access, and directory/create capability. URI text stored in SQLite is private lookup data, never authority by itself. A tracking row is reserved before permission take; failed and cancelled adoptions can leave an OS grant, which is disclosed rather than unsafely released.
3. The registry separates retirement (forgetting future selection) from irreversible invalidation (observed grant loss). Old admitted jobs may finish with retired-but-valid authority; old invalidated IDs never become valid when the same URI is newly selected. Provider unavailability or missing directory-create capability is not treated as proof of OS grant revocation. Existing exact-child readback/cleanup does not require the parent still to advertise new-child creation.
4. DB7 transactionally reconstructs A4a destination tables and adds the grant registry, preserving previous identities, source references, publication links, rowids, cursor and setting. All previous upgrade paths remain. No historical creation receives an admission or folder. Typed positive source versions and bounded validated decoders fail closed on malformed data. The frozen v6 schema remains unchanged.
5. The existing router and sole ExportCoordinator are reused. Folder admissions produce the existing SAF kind with the immutable per-operation grant ID; the Android adapter resolves only that operation's durable folder identity. It revalidates actual Android authority before create. The coordinator writes CREATE_INTENT before `DocumentsContract.createDocument`; the exact returned child is validated and durably bound before opening a writer. No existing document is selected by name or overwritten as a fallback.
6. A create side effect with no durable returned URI remains reconciliation-required. Restart/retry never creates a replacement, guesses a filename, adopts an unrelated document or deletes guessed output. Already-bound children can be reconciled/cleaned only through their exact operation mapping and currently valid authority. Ephemeral explicit CREATE_DOCUMENT export grants remain memory-only and are not restored through this registry.
7. Existing source and destination byte-count/hash/EOF verification, readback-unsupported distinction, handle-release ownership, cancellation and publication fencing remain. Extra-copy cancellation uses the same coordinator even before the router has created its record. Cancellation does not report provider cleanup as finished while a provider or handle is still outstanding. Settings/admission, folder grant adoption, copy routing and explicit export/control work remain bounded independent lanes. Every grant invalidation notifies a revision-fenced settings refresh independently of provider recovery completion.
8. Private publication and extra-copy status remain separate in the UI. Source rename/delete/version changes never silently switch the exact source. The external status can be pending, failed, cancelled, unverified or reconciliation-required without invalidating the private original.

## Required later Android acceptance

- Default/ASK/folder selection on every ordinary creation path, picker cancellation and permission denial, incomplete flags, read-only directory, system restricted folders, repeated taps, rotation, process recreation, stale callbacks and cancellation while permission/provider calls are in flight.
- Cloud-provider warning before consent; actual provider label/selection shown by the system; missing or revoked access offers explicit reselection without silently reviving invalidated operations.
- Repeated same-URI selection with continuously valid permission; partial or full revocation then same-URI regrant; forgotten or replaced selections with running, unverified or cleanup-pending jobs; registry-capacity handling.
- Local, removable and cloud-backed providers with root gone/offline, child moved, parent losing create support, unsupported write/truncate/readback/delete, corrupt/extra/truncated bytes and handle-release failures.
- Process death before create, between create and child bind, after bind, during copying/readback and around verified publication. All ambiguous outcomes preserve exact identity and prohibit a new automatic copy.
- Cancellation during blocked provider creation/write/readback, after final publication decision, and restart cleanup. A blocked provider must not spawn replacement workers or prevent independent private-media admission.
- Source rename/move/delete before copying, manual historical export remaining independent, no historical automatic copy, and original retention on every result.

## Official API context

Android DocumentsContract documents the tree-based access model, provider child identity and new-document operations: <https://developer.android.com/reference/android/provider/DocumentsContract>. Persistent permission is managed through ContentResolver: <https://developer.android.com/reference/android/content/ContentResolver#takePersistableUriPermission(android.net.Uri,%20int)>. These contracts inform the adapter; they do not replace device/provider acceptance.

### Picker correlation resource bound

The final folder picker uses a folder-only non-restored result bridge, not AndroidX's saved result registry. Request codes 42,000–65,534 are reserved, leaving recording's 41,320/41,321 and AndroidX's higher range unchanged. A synchronized private SharedPreferences counter is durably advanced before each launch and never reset or wrapped. Its 23,535 lifetime allocation bound fails closed with an explicit fallback notice. It stores only a correlation number, never a URI, grant, callback or ticket. An uncertain failed launch consumes its code. At most one process-local system picker remains outstanding; owner rotation drops its callback, and all late/cold results in the reserved range are discarded before the saved registry can see them. A pending old picker must finish or be closed before another launches. Synchronous counter commit and native result ordering still require device responsiveness/lifecycle acceptance.

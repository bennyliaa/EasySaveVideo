## Findings and disposition

1. **Malformed source versions could be coerced.** The initial v7 DDL admitted REAL positive source versions, and the row selector passed them to `Cursor.getLong`. The production owner added strict positive INTEGER DDL and read guards, preserving exact source identity rather than truncating malformed values. Independent SQLite regressions verify literal production SQL; no Android cursor coercion run is claimed.
2. **Cached selection after observed revocation.** The registry correctly clears durable selection when authority is lost, but the runtime initially continued displaying/snapshotting its obsolete in-memory folder. The owner added a durable monotonic selection revision and the production `FolderSettingsOrder` gate. Independent tests verify all 24 delivery permutations and equal-revision conflict rejection. The registry now signals invalidation immediately after its durable mutation; the export adapter forwards that signal, startup observer attachment reloads the setting, and the runtime coalesces revision-fenced refreshes on its bounded control lane. Independent registry/adapter tests verify notification after invalidation. The asynchronous UI integration remains source-reviewed, not Android-executed.
3. **Dynamic ActivityResult keys retained after normal callback completion.** Inspection of the admitted AndroidX Activity 1.10.1 bytecode established that `doDispatch` removes the launched key only after calling the app callback; `unregister` skips request-code/key removal while that key is still launched. Immediate unregister inside the app callback therefore leaves each completed random key in registry saved-state maps. The independent ordering model first reproduced two failures. Deferring normal unregister fixed completed-key retention but did not safely bound abandoned/restored keys. The owner therefore replaced this new folder-only path with a non-restored result bridge: an app-private durable counter consumes distinct request codes before launch, one process-local pending entry owns the callback, and stale reserved results are discarded before the AndroidX registry. No callback, URI, or grant authority is restored. Independent host regressions now cover normal completion, rotation/abandonment, late results, owner isolation, failed launch/persistence, counter corruption/exhaustion and concurrent allocation. The obsolete dynamic-key test doubles were removed; the admitted bytecode inspection remains historical finding evidence.

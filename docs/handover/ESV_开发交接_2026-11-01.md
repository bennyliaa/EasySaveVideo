## 3. 实际项目结构

以下以 [settings.gradle.kts](../../settings.gradle.kts) 为依据。默认工程包含 App 和 12 个 JVM 模块；Core 不接受 Android、Store 或 Provider 实现类型。

| 路径 | 当前职责与接手要点 |
| --- | --- |
| `app/` | Android 组合根、SystemWebView、UI、存储和系统适配；`app/src/main/.../save`、`recording`、`editor`、`library`、`vault` 等承接平台流程。不要再建立平行浏览器、导航或任务框架。 |
| `core-model/`、`core-domain/` | 平台无关模型、命令、权限能力、权益及状态机。Android 类型留在适配层。 |
| `ui-theme/` | ESV 对 SkinKit 的完整视觉默认值和快照适配，覆盖已有七类视觉契约。 |
| `discovery/` | Provider 调度、候选验证、结果池、进度与历史、会话预算和评估统计。 |
| `commons-provider/`、`searxng-provider/` | 原创 Commons、SearXNG 协议与解析、维护和隔离逻辑。来源配置与真实网络资格分别核验。 |
| `save/`、`hls/` | 平台无关 Direct/Stream 协调、恢复/提交契约和受限 HLS 解析。 |
| `recording/`、`library/` | 平台无关录制生命周期、片段规则及普通媒体目录/租约等。 |
| `verification-client/`、`verification-local/` | 可选验证服务协议客户端与本地 JVM 解析/验证路径。不能据模块存在推断真实站点效果。 |
| `verification-service/` | 原创独立 Python 验证服务和 Windows/Linux 适配代码，不是 Android Gradle 模块。原 `Scrapling_Service` 的开发来源已归拢，旧运行环境留在归档，不是新的开发入口。 |
| `verification-fixtures/contract/` | 独立夹具和调度契约子树，保留原历史，**没有接入 Android 生产引擎**。 |
| `nav-diagnostics/` | 仅在 `-Pesv.navdiagnostics=true` 时纳入的显式 QA 载体，不是生产 App 依赖；不要为普通开发自动开启。 |
| `scripts/`、`gradle/` | 现有边界检查、SQLite/宿主验证脚本、锁定和依赖验证。历史脚本适用范围要先读，不能为了跑过而改老门禁。 |
| `vendor/`、`third_party/` | 已固定的构件、原始元数据、许可证和准入证据。不是可随意升级或扩大的依赖仓库。 |
| `docs/`、`recovery/`、`artifacts/` | 需求、演进与测试证据、冻结交接和历史产物。出现 APK 或恢复包不等于当前已获装配/安装授权。 |

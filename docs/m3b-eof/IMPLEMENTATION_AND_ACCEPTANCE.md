# HLS EOF compatibility development integration

Status: host-verified development checkpoint, tag `m3b-hls-eof-dev-2026-10-06`. This is an Android 12+ phone/tablet development checkpoint, not device, package, production, or universal-HLS acceptance. No APK/AAB, install, device/emulator, real media transfer, account, publication or deployment has been performed.

## Practical integrity and supported scope

The received manifest-selected resources must finish their authorized transfers; the stored complete objects are bound by size, SHA-256 and local file identity before and after use. Clean complete unknown-length transfer retains the existing Direct-style semantics. A captured hash establishes that the received bytes did not change; without an independently trusted origin hash it cannot establish what the upstream author intended. A deliberately shorter valid source with internally consistent timing/manifest is acceptable. Malformed framing, incomplete transfers, lost remux samples and failed decode are failures.

The integrated original adapter uses only public APIs of the exact admitted Media3 1.11.1 jars. There is no Media3 fork, third-party source copy, new library, native dependency, runtime version migration, network fallback, source-byte rewriting or invented delimiter packet. The exact existing 72 runtime artifacts and closed-source SkinKit contract/default remain subject to admission checks.

The supported profile remains deliberately bounded: clear single-program 188-byte MPEG-TS; PAT/PMT per segment; progressive Baseline AVC I/P without B pictures or timestamp wrap; AUD-delimited one access unit per video PES; usable initial SPS/PPS and IDR; stable parameter sets; optional complete AAC-LC ADTS; strict monotonic sample PTS and gaps. Multiple slices of one picture, inherited SPS/PPS, ordinary non-IDR segment starts, and bounded or unbounded video PES are admitted. AU/PES/ADTS crossing segment boundaries, no-AUD or mixed-AUD, Main/High/B-frame broadening, discontinuities, retries, ranged reads, extractor recreation, encryption and unsupported tracks remain outside this checkpoint. This is a compatibility policy, not a declaration that all other streams are malformed. The structural scanner parses picture-identity prefixes, not full slice syntax or entropy.

## Shared extraction and ownership

Inspection and actual `HlsMediaSource` export both use `LocalHlsCompatibility`, the same wrapped AVC/AAC readers and final-access-unit gate. `TsExtractor` never sees a bare PES reader at intermediate chunk EOF, preventing its pinned scratch-header reparsing behavior. The final H264 callback occurs before final END_OF_INPUT only when a verified pending VCL AU makes the independent raw count exactly one greater than emitted count. Already source-delimited tails skip the callback; no empty phantom sample is accepted.

Each pass gets separate generation-bound resource receipts, constructed only from the existing private allowlisted capabilities. Receipt finality comes from the current opened resource, consumed parser position, exact received length/hash and approved last index. Playlist reads and peeking cannot grant finality. Ordered whole opens, sticky cancellation/failure and rejection of reopen, retry, range, rewind, foreign permit or recreation prevent borrowing an old successful receipt.

The engine keeps its underlying local-only source owner, absolute deadline, cancellation path, immutable-input posthashes, output inode/byte-cap checks, owned executor limits, rejected encoders/decoders and actual release fences. A timeout is not a release. Private atomic publication remains behind coordinator verification and commit/index receipt confirmation. Direct/free and Stream entitlement decisions are unchanged.

## Sample and timeline evidence

Raw AU/ADTS counts are checked against every extracted sample. Existing exact preflight-versus-mux relative-PTS, sync flag and entire raw payload digest checks remain. The durable contract is then generated from the actual mux-input timestamps, avoiding a rounding-phase assumption about the raw TS origin.

The canonical AVC representation changes only NAL framing: Annex-B start codes and specified framing zeros become four-byte big-endian NAL lengths; the NAL payload and order remain unchanged. AAC payload bytes are unchanged. Bounded constant-memory sequence hashes bind every sample index, integer track timestamp, flag, canonical length and payload, then total count and bytes. They also preserve final sample identity and the final GOP's preceding sync identity. Per-sample input limit stays 4 MiB, total samples 250,000. Timestamp conversion follows the pinned muxer's HALF_UP 90 kHz video clock and AAC sample-rate clock. AV edit-list offset is checked independently against the pinned 10 kHz movie-clock quantization; no accumulated segment tolerance is used.

The presentation endpoint includes a supported final display interval. At least three samples per admitted track are required for this checkpoint, matching the pinned muxer's duplicated-previous final-duration behavior. Established constant cadence gives a fixed endpoint; variable cadence gives a bounded interval from observed minimum/maximum deltas, not invented source timestamps. AAC-LC contributes 1024/sample-rate per frame. Original 100 ms segment-boundary and 350 ms total manifest consistency tolerances remain explicit; AV endpoints must be consistent within 150 ms. The reported representative duration uses the last interval while the durable VFR evidence retains its interval.

## Independent output and actual terminal decoding

New Stream output verification scans every Android `MediaExtractor` video/audio sample through actual EOF. It rejects changed count, timing, flags, canonical content, AV offset, final identity, phantom/config-only video samples and unaccounted tracks. Output bytes are hashed before and after native verification so evidence cannot silently bind a later same-size file change.

The verifier then seeks the independently identified preceding video sync sample, rereads and rechecks each final-GOP sample, queues all inputs and exactly one input EOS, and drains actual decoder output EOS. The admitted progressive no-B profile requires one accounted nonempty non-config output per input at its actual PTS, including the exact expected last presentation timestamp. EOS on a nonempty final frame is handled. Near-end START/MIDDLE/END probes remain additional existing checks; they are not terminal-AU proof. Early EOS, missing/duplicate/changed outputs, wrong sync, truncation, unknown flags, format changes, no progress, error, timeout or cancellation fail closed. Final compressed-GOP decode work is capped at 64 MiB; no-progress is capped at five seconds inside the existing absolute deadline.

Actual stop/release remains required before evidence can publish. A pure ownership gate closes the cancellation-versus-native-start race and holds the abandoned lane through a blocked stop/release. Native Android behavior remains a separate not-yet-run gate; decoder concealment means even successful device checks are practical validation of received media rather than universal proof of encoder entropy or author intent.

## Persistence and recovery

Save journal wire version 3 adds bounded platform-neutral conservation and tail evidence. Genuine v1/v2 records and legacy standalone evidence remain readable. No missing tail proof is fabricated. New Stream transfers require the full contract; legacy unproven Stream recovery defers or fails publication until valid evidence can be established. Direct legacy behavior remains supported. The private-media standalone evidence envelope is versioned separately. Unsupported future versions, invalid fields and trailing bytes fail closed. No destructive schema reset or old-binary rollback is implied.

## Verification scope

Host tests execute the actual pinned TS/PES/AVC/AAC reader bytecode, original parser and capability state machines. Synthetic entropy is not decoder-valid and factory/chunk calls are not the complete Android `HlsMediaSource` loading lifecycle. Pure verifier state tests cover sample loss/mutation, terminal output/EOS ordering, cancellation, no-progress and native ownership; they are not native codec execution.

Final strict offline verification passed 532 aggregate JVM tests with zero failures/errors/skips, plus 81 distinct pinned-reader capability tests and 15 actual pinned MP4 muxer/extractor roundtrip tests. The manually compiled 74 core/codec tests are a subset of the aggregate, not an extra count. Debug and Release compilation, both lints (zero errors, nine warnings and two hints each), exact 72-artifact admission, zero duplicate runtime implementations, source/debug-release/SkinKit boundaries, the legacy pinned-reader reproduction, 11 synthetic browser detector checks and host Discovery SQLite regression passed. The extra lint warning is a URI KTX convenience suggestion, not a suppressed safety error. No lint baseline, dependency or lock change was made.

Contact-absent and contact-configured build/unit states were rerun using an ephemeral synthetic contact, with no network request and no private contact embedded; the final build is restored to contact-absent. Commons implementation/configuration is unchanged. Independent review found no remaining source blocker in 16 changed/new production files; `evidence/reviewed-production.sha256` fingerprints them. Logs retain initial opt-in lint and cross-module test smart-cast failures and their successful fixes. See `evidence/verification-summary.json` and preserved JUnit/lint reports.

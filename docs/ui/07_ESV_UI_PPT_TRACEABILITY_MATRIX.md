## 3. 概念图的必要校正

| 图中差异 | 开发落实 | 验收处理 |
|---|---|---|
| PPT32保留API30/31差异处理措辞 | 后续复核源码AGENTS记录用户已改API31；正式基线归档替代关系 | 按本包API31测试，不降低minSdk；PPT作为早期视觉版本保留 |
| 部分画面五项底栏/设置在底栏 | 统一四项：发现、任务、录制、媒体库；设置顶部/侧栏 | 不以原图五项要求实现 |
| 图中播放三角、波浪等多个品牌图 | 同一候选ESV波浪标记，UI-B归档实际资产及许可 | 品牌未冻结不能自称已最终批准；保留统一资产即可 |
| 效果图显示12条/页 | 原规格建议20条/页，可配置；12只是示例 | 以实际场景记录，不强制图中数量 |
| 四策略的概念短文案不完整 | 以第01/05准确策略及语义为准 | T-10不按图片错字通过 |
| 英文首页曾出现Offline替代无痕 | 使用Incognito；不新增离线入口 | 本PPT英文展示页不替代完整语言资源 |
| 设置概念页未独立展示外观和语言 | 补外观/语言入口与详情，按现有组件风格 | T-05/T-31新增实际截图，可标PPT21/23扩展 |
| 高级录制/保险箱/购买图看似已可用 | 每动作注明REAL/DEMO/UNAVAILABLE | 不据截图判真实能力完成 |
| 图片设备边框、板外文字和海景宣传 | 不进入App；页面内装饰按许可/Token实现 | 截图对比去掉展示包装 |
| 切语言后文字变长、窗口不足收栏 | 允许换行、减列、收栏；关键动作保持 | 记录适配差异，不当成不符合效果 |

## 4. 实施版矩阵字段与截图命名

建议字段：`PPT页 / 页面ID / 组件ID / UiState或场景 / 真实-模拟 / 代码提交 / 窗口 / 主题 / 语言 / 字号 / 截图路径 / 测试ID结果 / 差异ID / 接受状态`。

建议命名：`P07_discovery-results_compact_light_zh-CN_fs100_DEMO-01.png`。中文/英文与深浅色使用同一素材ID；实际窗口dp、API、构建hash记录在截图索引，不靠文件名推断。私密相关截图只用公开样本；真实个人内容不得进入交付包。

第1/2/3/28～34页可将“截图路径”填写落实证据索引；其他页面应有对应真实App截图或明确缺口，不能只贴原PPT效果图作为完成证据。

## 5. 追踪完成规则

34行均有结果；UI-R01～14至少一项对应证据；C-01～12均覆盖所需状态；所有差异有影响和结论。P0/P1必须修复，待实现真实功能保留独立状态。后续修改PPT或Token时同步更新本矩阵及实际Golden，不让文档、图片和代码各自维护互相矛盾的规则。

# Framework reuse and dependency plan

SkinKit1.0.0 selected binary admission: third_party/skinkit-1.0.0/ADMISSION.md and IMPORT-MANIFEST.json. Reuse ui-theme and existing app Compose bridge. Active modules only Contract/Default, both1.0.0; no implementation sources. Existing registry, logical font sizes, subscription release, app defaults and business owners remain authoritative.

Current Foundation/Activity/Lifecycle/Media3/OkHttp/Jsoup/settings/thumbnail/save/record/library interfaces remain. Material3, official Compose navigation and official window-size input are UI targets; evaluate exact stable versions and transitive closure in a candidate configuration before integration. Keep runtime77 admission exact until a reviewed closure is recorded. No second DI, theme, navigation engine, downloader, encoder, image cache or settings transaction framework.

No Core/Personal/Animation/Store modules are required for this foundation upgrade. External SkinKit documents'17-module total does not mean ESV should depend on17 modules. Adding local skinpacks or photo themes later needs its own capability/lease/resource and binary admission checks.

2026-10-11 implementation update: official Android Material3 1.3.2, window-size-class 1.3.2 and Navigation Compose 2.8.9 admission is complete. Final runtime equality gate is 90 exact files (previous77 +13), with Kotlin2.2.10/Lifecycle2.8.7 retained. EsvText/EsvButton now adapt standard Material3 Text/Button while preserving detached SkinKit typography/colors/shapes and DISABLED > PRESSED > FOCUSED state priority. No new provider/encoder/cache/settings engine.

# Converted continuation: smallest connected candidate

2026-10-15 UTC. Read-only source investigation; candidate for review, not an approved design. No source edits, builds, test execution, devices, GitHub or network operations were performed by this task. The parent reports a full build in progress; this report makes no assertion about its result. Successful native producer execution and converted Android playability are still untested.

## Recommendation

Implement one cohesive **private silent WebM-to-MP4 chain**, through the existing Coordinator and owners:

closed-by-default private selection → same owned transcode run → finish → exact conversion-proof CAS → adoption → independent full silent AVC decode → exact verification CAS → existing typed commit/publication → terminal cleanup.

Do not ship only an adoption port or another standalone verifier. Once conversion can leave NORMALIZING, readable phase authority, recovery, cancellation and cleanup must cover every newly reachable state in the same change. This is one integration slice, followed later by native/device acceptance and the still-required Opus/AAC work before public admission. It does not need a second storage owner, durable DTO, schema, dependency, parser or executor.

## Verified current gaps

1. **Producer is ready to call, but has no caller chain.** `NormalizationAttemptOwner.runOwnedTranscode` and `finishOwnedTranscode` exist. `compareAndSetConversionProof` stores proof and removes checkpoint exactly. `DirectRawKind`, selection and `normalize` only expose MP4/MOV; `SaveCoordinator.runControlledLocal` rejects conversion records outright. The runtime has no WebM admission.
2. **Adoption mechanics already fit.** The workspace protocol already performs OUTPUT_READY → ADOPT_INTENT → ADOPTED with exact P→raw.bin and output.mp4→P no-replace moves and directory fsync/readback. Its adoption proof parameter, owner wrapper, ledger authority and adapter checks are MOV-only.
3. **Phase/authority gates are hard blockers, not cosmetic typing.** `NormalizationDurableMutationPolicy.permitsPhase` rejects all conversion phase changes. `AndroidSaveStorage.normalizationAuthority` requires conversion to remain NORMALIZING without verification/receipt. `NormalizationJournal.requireNormalizationAuthority` accepts only MOV in ADOPT_INTENT/ADOPTED. Changing only `adopt` would produce unreadable or unmanageable state.
4. **The canonical read owner can be reused.** `AdoptedCanonicalOutputOwner` already reserves before IO, opens the adopted P once, captures parents/inode/extent, verifies raw.bin/absence of output.mp4, fences full Save/ledger/catalog snapshots and positively closes on its worker. Binding requests, acquire/lease signatures and the authority proof branch are MOV-only. `AndroidLocalMp4Verifier` explicitly rejects ConvertedDirect before its sole native lane.
5. **Independent decode already exists, with one missing scalar.** `BorrowedAvcAacInspection` calls the independent flat-MP4 probe, complete sample walk and complete AVC decode through real output EOS, then releases native resources. Its successful observations contain dimensions, duration, frame count and endpoints. They do not contain the maximum absolute deviation of **every** video timestamp from the fixed zero-origin CFR clock; endpoints alone cannot establish that conversion-proof field. Silent verification can use this implementation without importing Editor assumptions or changing its audio policy.
6. **Commit mechanics already fit; policy is MOV-only.** `NormalizedCommitProtocol` and its SQL journal already own provisional intent, exact file promotion, fresh final rehash, invisible index and atomic Save/Library/destination publication. Their active descriptor/proof checks reject conversion. Conversion cleanup is deliberately restricted to unpublished NORMALIZING/OUTPUT_READY; it must expand with the chain. Existing `VerificationEvidence`, `DirectConversionVerificationProof`, codecs, selected descriptor, Library publication validation and workspace v2 already support the required durable shape.

## Minimal integration sequence and interfaces

### A. Connect the private caller, keeping public gates shut

Add a distinct `WEBM_CANDIDATE` raw selection and a distinct `ControlledDirectStorage.convert(...) : DirectConversionProofCompletion`, default-failing for other implementations. Do not change MOV's completion type or put both producer proofs in a nullable union. A bounded EBML signature check on the existing owned raw-probe view is only branch selection, never profile acceptance; the existing paired WebM probe remains the complete authority inside the same transcode attempt. Do not add a second full WebM parser/preflight or replenish its run budget.

Use one independent closed-by-default pipeline execution switch for this private branch; production construction stays false and public MIME/network/UI admission stays unchanged. It is routing configuration, never execution authority. Private composition tests may select the branch with an owned local fixture; a flag alone grants no Scope, reader, writer or publication. Do not reuse the MOV switch. The Coordinator must reject a selected WebM candidate before prepare/writer issuance when this switch is false, and reject converted recovery before continuation when false.

The adapter validates its exact issued Selection, original completed raw snapshot, fresh/no-legacy provenance, original Scope/context/permit, and the precise NORMALIZING successor. It then calls existing `prepareTranscode(..., selection.token, selection.scope)`, `runOwnedTranscode(attempt)` and `finishOwnedTranscode(attempt)`. Keep the outer Selection/Scope live through the exact proof CAS/readback; closing the old attempt must not revoke the handed-off token. Close completion and selection only afterward. No extra attempt, timeout, budget, batch or HTTP retry. Preserve the selected original failure and separate sticky resource uncertainty when mapping errors to Save errors.

### B. Adopt using existing roles and owner

Add `DirectConversionProof` overloads to adoption-intent methods; make the existing owner `adopt` select exactly one current proof branch. Extend existing durable phase policy narrowly for the same legal edges as MOV, bound to the full conversion proof and exact ledger row: NORMALIZING→ADOPTING at OUTPUT_READY/ADOPT_INTENT; ADOPTING→VERIFYING at ADOPTED. Verification→COMMITTING evidence issuance remains typed CAS. Keep ordinary control revisions, stop-only active-read policy, and immutable data fields intact.

Extend SQL authority to these exact phase/lifecycle/evidence/catalog combinations, rather than deleting its producer restrictions wholesale. Require current silent policy, no MOV proof, no checkpoint, exact source/raw/output/digest/generation and expectedAudio=false. Adopt only after acknowledged producer CAS. Reuse all rename uncertainty and fsync/readback logic; no fresh writer or new generation on recovery.

### C. Use the same adopted owner and borrowed inspector

Add a ConvertedDirect overload of the existing canonical owner's acquire port. The existing lease and internal binding can carry the existing sealed `ArtifactOutputDescriptor`, with an exhaustive MOV/ConvertedDirect branch and explicit rejection of Transferred. Keep exact object identity checks; do not create another owner or a new descriptor hierarchy. Give the converted overload its own preflight, leaving MOV policy unchanged.

Add a small converted adapter to the existing `AndroidLocalMp4Verifier` native lane. It acquires the adopted lease on the actual worker, forms `BorrowedAvcAacRead` from that lease's original FD/channel/fixed extent, verifies the expected hash, invokes the existing borrowed inspector with the conversion video's dimensions/rate/duration/frame count and `Silent`, then verifies actual native release, the same descriptor's final hash and the live adopted identity/snapshot before closing the lease. Return usable evidence only after positive native and owned RAF release. A cancelled Future is never release. No legacy pathname, MOV conservation parser/tail proof, Editor executor/gate, or reopening P.

Minimum observation extension: add one explicit `maximumFixedVideoDeviationUs` scalar to existing `AvcAacOutputObservations`, with no zero/default success fallback. Compute it from every observed `videoScan.samples[index].ptsUs` against `floor(index*1_000_000/frameRate)`, with checkpoints and bounded arithmetic. Return it only after the existing full decoder ledger has proved one-to-one exact PTS equality for every scanned sample and actual output EOS. Thus this is a measurement over all independently observed and decoded frames, not a maximum inferred from endpoints, copied from the producer, clamped to tolerance, or inferred from compressed VP8 counts. The converted adapter enforces ≤1,000 µs. The existing Editor acceptance rules and audio tolerances remain unchanged; its relative-clock policy is not silently tightened. No new decode-result DTO is necessary. Successful inspector return already requires complete container/sample walk and video EOS; use that contract plus actual native-release state, not fabricated booleans from producer facts.

The adapter builds existing `DirectConversionVerificationProof` using measured independent output facts, producer digest/identity and the same verified output hash. Silent audio fields stay null and observed audio counts must be zero. `VerificationEvidence.isValidFor(ConvertedDirect, expectedAudio)` remains the final shape/policy check.

Important small lifecycle extension: retain the **actual BorrowedAvcAacInspection object** if native release is uncertain. Its current contract explicitly requires this. Reuse the existing poisoned adopted reservation/strong failed-owner root, e.g. an opaque retained-resource overload of the existing lease uncertainty latch, instead of a new owner/registry. Keep the no-argument MOV latch behavior. For converted inspection with unconfirmed native release, retain the inspection and original lease/read under that existing poisoned owner rather than entering the success final-hash/close-release path; do not close the borrowed descriptor while native use is still unconfirmed. If native release succeeds but stop or inspection failed, close the read normally and preserve the original failure. Mark uncertainty memory-only; never run callbacks or IO under the owner lock. Also confirm that the exact production binding was actually consumed and its read positively released before the adapter issues verification completion; an unconsumed binding plus a caller-constructed evidence DTO cannot be success. An in-memory release witness on the existing Binding suffices; no durable token is needed.

### D. Reuse typed verification and commit

Add ConvertedDirect overloads of `verifyNormalized`, `beginNormalizedCommit` and `inspectNormalizedCommit`; reuse `DirectVerificationCompletion`, `NormalizedCommitHandle`, `NormalizedPublicationHandle`, their identity registries and existing journal CAS methods. Private shared code may hold the existing descriptor and reject Transferred exhaustively. Remove the unused MOV-only `VerificationCommitFact.proof` field or replace it with the already-selected descriptor; do not add two nullable proof slots.

Verification issuance checks the same exact VERIFYING Save/ADOPTED row, positive owner release, actual live execution and current independent evidence, then reserves the existing VERIFY handoff. CAS rechecks the registered completion and exact revision/proposal. Add explicit revision-overflow rejection at the reused CAS boundary.

Commit's converted active branch must check current silent producer policy and independent evidence, raw+output budget, exact ADOPTED generation, execution/control identity and catalog state. Keep intent→promotion→invisible index→fresh final digest→PUBLICATION token→atomic Save SUCCEEDED/Library/destination binding ordering unchanged. No generic commit/CAS, producer-only publication or reconstructed handle. The SQL adapter independently validates the same converted binding and terminal policy; `binding` must no longer delegate conversion exclusively to its narrow producer-terminal predicate.

## Recovery, history and cleanup policy

- Missing proof, WRITING, orphan OUTPUT_READY, foreign/mismatched rows and uncertain release remain REVIEW. Never reconstruct a producer completion/proof from a workspace digest. Raw retry follows existing genuine transfer-release/startup provenance; local failure never reopens HTTP.
- Under the private branch only, current silent proof with exact OUTPUT_READY/ADOPT_INTENT plus READY/RAW_MOVED/ADOPTED layout may return ADOPT; exact ADOPTED without evidence may return VERIFY. Evidence-bearing COMMITTING + ADOPTED may return COMMIT for STAGING before first commit intent, or matching invisible INTENT/INDEXED, only through fresh typed reconciliation of the actual canonical/final role. For STAGING, Save.verification must already be the valid exact independent evidence, catalog.evidence must still be null, and the existing canonical P plus original raw.bin must be physically revalidated; then the existing begin method writes the first intent. Missing evidence never qualifies.
- Distinguish structural/historical readability from active admission. Preserve historical MOV audio-policy-1 behavior and existing codecs. Do not upgrade old evidence, add audio facts, treat a completed record as new execution, or let a switch override current policy. Audio-bearing conversion stays REVIEW/rejected for active continuation in this silent slice.
- Expand exact FAILED/CANCELLED cleanup for OUTPUT_READY, partial ADOPT_INTENT, ADOPTED and invisible provisional commit, using the existing inode-bound role plans and same-database revocation of an exact invisible index. Preserve the prior producer-only cleanup cases. Cancellation after verification/commit intent must remain recoverably cleanable.
- Add SUCCEEDED temporary-raw cleanup only after the exact visible publication; never delete/reopen/recreate the canonical final file, and do not recreate a Library item deleted or edited later. Historical v1 cleanup plans without identities remain readable but cannot gain invented deletion authority.

## Acceptance boundary

Host work should prove policy, ordering, identity races and composition using clearly labelled synthetic OS/native seams, never claim successful native codec execution. Require a connected private Coordinator orchestration test, plus positive Android end-to-end run/decode/commit later on the separately authorized device path. Do not add a production run-success injection seam merely to make a host test green.

The remaining required product chain includes detected Opus source PCM continuity/EOS, actual delay/preroll/discard-padding handling, AAC encoding and independently mapped AAC presentation verification. Keep Opus intact and reject it now; optional source audio is not permission to drop it. Public admission and device acceptance are separate later decisions.

## Review corrections, revision 1

The current canonical close calls binding.complete(), revokes it and removes the registry entry. Verification issuance must therefore not call requireLive on that retired binding or require it still be registered. Keep a private immutable consumed-and-positively-released terminal witness on the same exact Binding/State. Only the exact canonical owner closing the matching consumed read with confirmed native and RAF release may record it; foreign/unused/uncertain/late callbacks cannot create it. General complete/revoke/cancel is not this event. Adapter issuance verifies this historical exact witness while separately checking the original live Scope, permit and unchanged Save/ledger snapshot. A successful read close can precede a later stop; that stop forbids completion issuance without erasing the historical release fact. The witness grants no IO, new registration or publication by itself. Add positive post-registry-removal issuance, unconsumed/caller-forged evidence rejection, close failure, late callback and stop-after-close negative tests.

Converted verification has an explicit boundary error mapping before the existing native lane Future returns: preserve an existing SaveFailure instance and its CANCELLED/DEADLINE_EXCEEDED/RESOURCE_CHANGED/storage/etc. code; map AvcAacVerificationFailure.VERIFICATION_FAILED to INVALID_MEDIA, UNSUPPORTED_PROFILE to UNSUPPORTED_MEDIA, TIMEOUT to DEADLINE_EXCEEDED, and RELEASE_UNCONFIRMED to RESOURCE_RELEASE_UNCONFIRMED. Actual local IOException/SecurityException follows the existing local-storage mapping; other platform/native call failures map to VERIFICATION_UNAVAILABLE, not arbitrary INVALID_MEDIA from the outer ExecutionException fallback. At a failed IO boundary, select original context cancellation/deadline before publishing a derivative IO reason, and keep an already selected primary stable. Native or RAF release uncertainty is independently latched and strongly retained even when a prior cancellation/content failure remains the thrown primary; no usable completion may be returned. Successful-native-release but stop failure remains ordinary verification failure and closes the read. Editor error mapping stays unchanged. Tests execute the production mapping and real existing executor/lease seam with fake native bodies, covering original caller errors through ExecutionException, both release outcomes, and cleanup failure after an already selected primary.

The normal crash window after verification typed CAS but before commit intent (COMMITTING + ADOPTED + STAGING, Save.verification present, catalog.evidence null) is explicitly recoverable. Add a genuinely new owner/protocol fixture for this checkpoint, both COMMIT continuation and exact Cancel cleanup. Preserve the same proof/evidence, raw/output hashes, generation and inode roles; recovery does not repeat conversion or independent decoding merely to manufacture evidence.

The retained converted inspection contract also applies inside AdoptedCanonicalOutputOwner.closeOwned. Once converted native release is unknown and the actual inspection object has been retained, every later lease.close, enclosing Scope cleanup, repeated/late close and cancellation may only revoke/retain that same obligation. They must not invoke RAF/FD close while native borrowing remains unconfirmed; a later callback cannot silently clear the sticky state or retry release. Implement this narrowly in the converted retained-resource branch, preserving existing MOV no-argument behavior. Add unknown-native-release followed by late/duplicate close tests asserting zero RAF-close calls and retained inspection/read/owner; separately prove positive native cleanup precedes exactly one RAF close and terminal release witness. No new registry or owner is required.

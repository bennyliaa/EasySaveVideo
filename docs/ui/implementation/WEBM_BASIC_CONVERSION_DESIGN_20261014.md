## 1. Recommendation and actual user value

Add one coherent free Direct conversion profile: **a complete, owned WebM file containing VP8 video, with no audio or one Opus mono/stereo track, converted to independently verified H.264/AAC-LC MP4 through the admitted Media3 1.11.1 Transformer.** Begin with the existing Editor's finite SDR, geometry, duration and CFR budgets. Retain the same dimensions, visible-frame cadence, audio presence and channel count. Do not introduce cropping, scaling, compression presets, paid-tool checks, or recording fallback.

This targets actual downloadable WebM clips with sound, rather than a synthetic silent-only format. It does not cover all contemporary WebM: VP9, AV1, Vorbis, VFR, audio-only files, multiple selectable tracks and streaming segments remain outside this first engineering profile. No frequency or coverage percentage is claimed without a real corpus. Unsupported files receive an honest unsupported result, not a successful extension change.

**Why conversion:** the pinned `Mp4Muxer.SUPPORTED_VIDEO_SAMPLE_MIME_TYPES` includes VP9 but not VP8. The selected VP8 video therefore cannot simply pass through that muxer. The selected output policy is H.264 plus AAC-LC because ESV already has a strict independently decoded verifier for that profile. Importantly, the same muxer *does* list Opus and Vorbis audio: do not claim MP4 intrinsically forbids them. Choosing AAC-LC for this slice is a compatibility/reuse decision that introduces audio encoding loss, not a physical impossibility of Opus-in-MP4. A later Opus-preserving output would require its own compatible output-verification/playback acceptance; it is not silently included here.

This is **not ready to enable after a device check alone**. Design review, a shared-mechanism extraction, real Direct/storage wiring, schema/evidence changes, host regression and native/quality acceptance remain. The admitted dependency graph contains the required mechanisms; no new dependency approval is identified.

## 2. Requirements versus additional engineering policy

The original product requirement, PR 7.1 (`01_Product_Requirements.md:205–217`), makes Direct free and says feasible basic compatibility conversion belongs to its normal output path. TR-06 (`04_Technical_Requirements.md:121–169`) requires actual container/codec inspection, remux or conversion when feasible, explicit unsupported results, protected-media refusal, cancellation, budgets and verified atomic publication. Its unified condition explicitly says every long video need not be fully decoded. The architecture says basic compatibility belongs to SaveEngine; user-invoked compression/crop belongs to advanced tools (`02_Architecture_and_Data_Model.md:373`).

Necessary implementation boundaries remain: exact owned input/output identity, no unapproved remote reads, DRM refusal, no lost selected media track, bounded work, cancellation/deadline, actual native-release acknowledgment, no late publication, independent playable-output evidence, and unchanged HTTP accounting.

The following are **our engineering choices**, not additional user requirements:

- Only VP8 and optional Opus in this first profile; integer CFR, even dimensions, SDR/square pixels, finite duration/bytes and bounded track count.
- H.264/AAC-LC as the first supported MP4 target; complete output decode is a reuse choice for this bounded conversion, stronger than original sampling requirements.
- A trusted-parser/codec model: Media3 and Android interpret EBML, VP8 and Opus elementary content and ordinary codec delay/padding. ESV checks ownership, track inventory, declared/observed metadata, finite resource use and real resulting output. No new EBML demuxer, VP8 bitstream validator, Opus packet parser, decoder, or proof of individual compressed packet consumption is required.
- No exact compressed-byte/sample conservation between different codecs. An Opus packet is not an AAC packet; a VP8 compressed sample is not necessarily one displayed frame. Invisible/reference-only frames must not be counted as user-visible frames by assumption.

The existing approved AAC trust design makes the same distinction between playback acceptance and a stronger bespoke syntax proof. Its remux conservation is appropriate to same-codec remux; it must not be imported as a false transcode requirement.

## 3. Finite initial input and output contract

### Input candidate

- Fully downloaded, self-contained, ordinary WebM (`DocType=webm`), no playlist, external data source, encrypted track, linked segment, unbounded live input, or additional media track. An unknown-sized EBML Segment/Cluster is not itself live or incomplete: a complete fixed owned file can use those encodings, subject to the bounded EOF rules in section 5. One VP8 video; either zero audio or one Opus track. Page `expectedAudio=true` requires actual audio, while `false/unknown` does **not** authorize dropping actual audio.
- Reuse current limits: raw/output each at most the effective operation limit and 2 GiB; duration at most 30 minutes; even width/height, each at most 1920 and total at most 1920×1080 pixels; integer 1–60 fps; at most 108,000 *displayed* video frames. These are budgets, not device-performance promises.
- VP8 normal 8-bit SDR presentation, square pixels, no crop/rotation/projection/stereo/alpha semantics that would be silently discarded. Fail unsupported on nontrivial presentation metadata rather than inventing conversion effects. Missing ordinary SDR color labels may use the trusted library's normal SDR default; explicit HDR/inconsistent decoded color rejects. Do not require a handcrafted VP8 color parser.
- Opus decoded at 48 kHz, one or two channels; preserve mono/stereo. Carry the library-produced Opus initialization data unchanged, including codec-delay/pre-skip and seek preroll. Bound configuration to 64 KiB, sample data to 4 MiB, aggregate configuration/metadata and total element/sample counts. Proposed finite boundary allowance: at most 120 ms each of codec delay, seek preroll, final discard padding and source preroll. This is a reviewable resource/compatibility limit, not proof of Opus syntax.
- Source timestamps/duration are observations from the trusted demuxer. Allow ordinary bounded Opus preroll/negative prefix; do **not** reject Opus solely because a raw timestamp is negative. The visible video timeline must be observed as integer CFR within the existing 1,000 μs quantization allowance. WebM millisecond timebases naturally need rounding allowance. No frame-rate effect is applied to turn VFR into apparent CFR.
- No identifying metadata is copied into the new MP4. Non-media tags may be bounded/skipped; text, auxiliary, alternate or unknown track entries are not silently skipped. Chapter/attachment/linked-segment semantics outside this profile are rejected rather than advertised as preserved.

### Output and quality

One H.264 video, physically same width/height, rotation zero, 8-bit SDR/square pixels, no B-frame reordering, and the source's accepted visible CFR timeline; one AAC-LC 48 kHz mono/stereo track exactly when input audio exists. Silent input stays silent. Use existing original-quality bitrate policy as an explicit starting encoder policy: `width × height × fps × 0.16`, bounded to 256 kbit/s–20 Mbit/s, and AAC 96/192 kbit/s for mono/stereo. These are requests, not guaranteed achieved rates or lossless quality.

Request no decoder/encoder/format fallback, no tone mapping, no resize/crop, no remove-audio option. On inability to create the selected codec/format or on a fallback callback, fail clearly. Do not retry with lower dimensions or silently discard audio. Decoder availability queries alone never establish conversion success.

User copy must say this is a free compatibility conversion, that processing takes extra time, and that re-encoding may change picture/sound quality. Do not call it lossless or promise smaller size. TR 5.3 explicitly calls for reason/time/output-quality explanation when transcoding; extending that honest explanation to Direct needs no new purchase decision. No unresolved commercial choice is required to implement this design. A proposed confirmation dialog would be UX policy, not a hidden requirement for free conversion; the minimum is visible status before conversion with ordinary Cancel.

## 4. Exact admitted APIs and reuse limits

Pinned source JARs were inspected in `third_party/candidates/media3-1.11.1/sources/`. They are evidence, not new source copied into production.

- `MatroskaExtractor` is public and non-final. Its `sniff/init/read/release` are final, but `getElementType`, `startMasterElement`, `endMasterElement`, `integerElement`, `floatElement`, `stringElement`, `binaryElement` and `getCurrentTrack` are protected extension points. The constructor `(SubtitleParser.Factory, flags)` exists. Use `SubtitleParser.Factory.UNSUPPORTED`, disable seek-for-cues during the linear inventory pass, and disable HAGC metadata. Do not try to instantiate package-private `DefaultEbmlReader`/`EbmlReader` directly.
- `MatroskaExtractor.endMasterElement(TRACK_ENTRY)` silently ignores unsupported codec IDs before reporting tracks. A protected-callback policy subclass can count **every** TrackEntry and reject unsupported/duplicate/extra/protected tracks before calling `super.endMasterElement`. This is materially stronger than merely comparing the AssetLoader's selected track count, without implementing EBML parsing.
- `MatroskaExtractor` already provides Opus identification, codec-delay and preroll CSD; its Opus `DiscardPadding` travels as supplemental sample data. Preserve that official path. Do not interpret supplemental data as encryption or strip it merely because MOV remux forbids it.
- `ProgressiveMediaSource.Factory(DataSource.Factory, ExtractorsFactory)` and `ExoPlayerAssetLoader.Factory(app, decoderFactory, Clock.DEFAULT, mediaSources, null, null, loadControl)` are already compiled in `Media3EditorEngine`. Substitute the bounded WebM extractor factory and a storage-issued private local data source.
- `Transformer.Builder`: `setLooper`, `setAssetLoaderFactory`, `setEncoderFactory`, `setVideoFrameProcessorFactory`, `setMuxerFactory`, `setVideoMimeType(VIDEO_H264)`, `setAudioMimeType(AUDIO_AAC)`, `setPortraitEncodingEnabled(true)`, `setUsePlatformDiagnostics(false)`, disabled trim optimizations, bounded max frames/delay, and completion/error/fallback listeners are all used in the existing engine.
- One `EditedMediaItem`, no trim configuration/effects, one `EditedMediaItemSequence`, and `Composition.setTransmuxVideo(false).setTransmuxAudio(false)`. `audioNeedsEncoding/videoNeedsEncoding=true` remains the explicit encoding policy. **Do not call `EditedMediaItem.setFrameRate`**: the existing Editor review found that frame-rate targeting may discard frames.
- `DefaultDecoderFactory` and `DefaultEncoderFactory` already wrap Android codecs. Existing no-fallback settings and AVC/AAC encoder settings are reusable; the input allowlist must be parameterized for VP8/Opus rather than weakening Editor's AVC/AAC allowlist.
- `Mp4Muxer.Builder(SeekableMuxerOutput)` plus batching disabled and streamable output disabled, as used in `EditorBoundedMuxer`, gives a bounded seekable sink including final tables. The supplied Transformer path remains an internal exact-match token; the custom muxer must open the already-owned output rather than an arbitrary user path.
- `Codec.releaseOutputBuffer(long)` exists for the actual rendered video presentation timestamp. Source-visible count/CFR observations are **mandatory** for this conversion proof and use the exact held-buffer contract below. They are observations of the trusted decode path, not independent source-pixel proof.

### Mandatory displayed-frame observation and time basis

Bind the observation decorator only to the exact VP8 decoder returned by the registered decoder factory for this attempt; an encoder, another attempt or another codec cannot supply these facts. The public Media3 `Codec` interface exposes no native output-buffer index. Do not use reflection or invent one. Its documented contract exposes exactly one current output buffer until release; use a monotonically issued **local pending-buffer token** for that lifetime, with a copied `BufferInfo` tuple, not the identity of its reused mutable `BufferInfo` object.

- On the first non-null `getOutputBufferInfo()` for the held lifetime, copy PTS/offset/size/flags and issue the token. Repeated get calls return the same pending observation without incrementing count; inconsistent changes while still held fail. `getOutputFormat()` can itself dequeue internally, so it cannot count a frame. The following actual info call binds that current buffer.
- On `releaseOutputBuffer(long localPtsUs)`, require that exact unconsumed pending token, validate its finite fields and deadline, then delegate exactly once. Only **successful return** appends one displayed-frame observation and consumes the token. A throwing/uncertain release never appends or retries and makes conversion evidence unavailable, retaining normal native cleanup obligations.
- `releaseOutputBuffer(false)` consumes/discards the pending token only after actual successful release and contributes zero displayed frames. The pinned video renderer uses this for negative/decode-only/target-rate drops. The Direct run never enables target-rate dropping. `releaseOutputBuffer(true)` is a different overload that uses the buffer's renderer PTS; the pinned accepted path uses the long overload, so an unexpected true call in this Direct profile reports unavailable, contributes no observation, and still executes required native cleanup rather than substituting a clock or abandoning a live buffer. Editor's existing overload behavior remains unchanged.
- A Surface decoder's valid rendered buffer is not counted by `size>0`; it is counted by its successfully released/rendered lifetime. Pinned `DefaultCodec` consumes codec-config and empty EOS buffers internally; neither is a displayed observation. Actual decoder input EOS, eventual `isEnded()`, no pending external buffer, complete Transformer success and actual session cleanup are all required before finalizing the ledger.

Pinned `ExoAssetLoaderVideoRenderer` first computes `localPtsUs = currentBufferInfo.presentationTimeUs - streamStartPositionUs`, then requires `sampleConsumer.registerVideoFrame(localPtsUs)` to succeed, and only then calls the long release overload. This long argument is therefore the local presentation time to observe; **do not subtract it again, and never subtract the first emitted frame**. `BaseRenderer.readSource` adds renderer offset, while the renderer start is the period start plus that offset. This run has exactly one complete item, media start zero, no clipping, no seeking/resume, no speed effect, and composition item offset zero. Its bound source-video timeline origin is zero, so the long argument is directly its source/composition-local presentation time; renderer offset is not a durable media timestamp.

Fix that origin in the admitted run-spec before any decoded output. Require the demuxed source-video start and first displayed time to be within 1,000 μs of that zero; a positive delayed first frame must not be rebased to hide a missing head. Check every displayed PTS for strictly increasing order, the absolute integer-CFR lattice and individual step (≤1,000 μs quantization), count 3–108,000, and final endpoint/count-duration agreement with the independently observed source duration (one nominal frame plus 1,000 μs maximum endpoint tolerance). Missing head/tail or a changed time basis fails even if output alone decodes. Do not derive the source duration from the output to make it agree. The ledger transports bounded count/first/last/cadence/duration facts, not compressed packet conservation; invisible VP8 packets are not assumed to display a frame.

Required wrapper tests cover repeated info calls, mutable info reuse across distinct lifetimes, info dequeued through format polling, zero-size valid Surface output, false-discard, unexpected true overload, successful long release exactly once, throwing release, pending-buffer EOS, nonzero renderer offset with local zero, and delayed first-frame/tail loss. An actual pinned render-drain fixture must corroborate the time basis; fake observer counts alone do not pass the native gate.

### Independent source-audio boundary and output-audio endpoints

Do **not** rename arbitrary decoder PCM as “audible source after all trimming.” The pinned pipeline has separate clocks and possible graph processing. Two observations are mandatory and use existing public interfaces:

1. **Source/consumer-side ledger S:** the existing `AssetLoader.Listener.onOutputFormat(format)` wrapper recognizes the selected `audio/raw` output and decorates the returned public `SampleConsumer` (preserving null/backpressure behavior). Its `getInputBuffer()` returns the delegate's exact current `DecoderInputBuffer`; immediately before `queueInputBuffer`, snapshot that buffer's original local PTS, remaining PCM bytes, EOS and checked PCM16/rate/channel format. Call the delegate once and commit the observation **only when it returns true**. A false return retains the same pending buffer for a retry and adds nothing; a throwing/uncertain call cannot mint evidence. Copy only bounded primitive metadata before delegation; the ledger must not retain a mutable ByteBuffer/BufferInfo reference or inspect buffer state after a successful delegate may have reset/reused it. Count sample frames, continuity, first/last presentation time and EOS, with fixed limits and no PCM file. This observes PCM actually accepted into the official graph, not merely decoded or copied before backpressure.
2. **Graph/encoder-side ledger E:** wrap only the exact AAC encoder returned by the registered `Codec.EncoderFactory`. Before its `queueInputBuffer(DecoderInputBuffer)`, snapshot the graph-output PCM buffer's remaining bytes/format/EOS; commit bytes/sample frames only after successful delegate return. Pinned `AudioSampleExporter.maybeFeedEncoder` generates encoder PTS from cumulative PCM bytes starting at zero, so those PTS **must never establish or replace the source start**. This is the post-graph PCM extent actually submitted for encoding.

Keep terminal facts separate: (a) owned raw/extractor actual EOF with no partial sample, (b) decoder input EOS queued and output actually ended, (c) the source PCM consumer accepted EOS (`queueInputBuffer()==true`), (d) post-graph AAC encoder input EOS successfully queued, and (e) AAC encoder output actually ended/drained, muxer finalized and session released. No one Boolean stands for another. Public codec/consumer hooks and pinned successful completion establish their respective facts; do not invent a public AudioGraph EOS callback. Consumer backpressure, a late callback or zero bytes never substitutes for the missing terminal acknowledgment.

Source basis: pinned `ExoAssetLoaderAudioRenderer` subtracts `streamStartPositionUs` from compressed input timestamps; its decoder output `BufferInfo.presentationTimeUs` is copied unchanged to the SampleConsumer buffer. `AudioGraphInput.queueInputBuffer` records the first successfully accepted time. S preserves that source-local time, under the same full-item start-zero/no-clipping/one-item composition contract as video. Never subtract S's first PTS or use E's zero-based encoder clock to hide a delayed source. Repeated buffer polls, backpressure retries, discarded decoder data and cancellation cannot create extra accepted S/E samples.

For this initial no-effects/no-resampling/no-channel-change profile, admission requires checked 48 kHz/mono-or-stereo PCM16 on both sides, complete S and E EOS, continuous S timing and **equal total S/E PCM-frame counts**. The source/graph relation may not silently spend an Opus or video allowance on trimming, silence append or loss. `AudioGraphInput` contains a silence-appending stage even without user effects; equality plus S's independent endpoint prevents its fill-to-video behavior from concealing a short source track. This is a narrow PCM-boundary consistency check for the selected official path, not compressed packet conservation or waveform equality.

The intended audible-source start/end can be bound to S only after the selected official decoder/CSD and graph behavior is established for the admitted Opus profile. The first native engineering fixture pass must determine where codec delay/preroll/discard padding are applied and compare S/E with known audible head/tail markers. Raw decoder release alone, identical counts, or renamed fields cannot prove this mapping. **This relation is currently unverified.** If legitimate trim is applied after S, or padding survives into E, the current equality/endpoint contract rejects that case; identify its actual public processing boundary or a specific verified delay mapping and review that small amendment before admission. Do not infer effective audible endpoints from E alone, silently relax bounds, or add an Opus parser. A generic AudioProcessor byte counter without timestamps would not by itself solve the missing source-origin problem.

This first profile admits accurately co-starting/co-ending playable tracks once that mapping is verified: source audible start is within 1,000 μs of the **fixed common source origin zero**, and independently observed audible end/effective PCM duration agrees with the admitted source-video endpoint within 1,000 μs including sample rounding. Legitimately shorter/delayed/longer audio is unsupported in this first profile; it is not padded, clipped or separately rebased. Source Opus delay/preroll/discard limits of 120 ms bound supported metadata/input handling; they are not permission to lose 120 ms of audible content. Raw negative Opus preroll is not itself rejected when the trusted handling produces the accepted presentation.

Persist source audible start/end/effective PCM-frame count only after the checked S/E relation, real source-boundary mapping and actual session completion, together with 48 kHz/channel facts. The shared inspection profile has a **Direct-specific independent audio expectation**, separate from video duration/tolerance. Compare the output audio's mapped presentation start, final end and effective decoded PCM duration with those source-audio facts. Each head/tail difference and effective-duration difference is bounded by the selected AAC allowance: **at most 42,667 μs inclusive of rounding, never plus the video frame tolerance or Opus 120 ms**. Apply the common source/composition origin and parsed output edit-list/encoder delay mapping; do not subtract each track's own first timestamp. Interior continuity uses only sample-clock rounding. Correct movie/video duration cannot compensate for a missing audio tail.

Current `EditMp4Probe`, sample/audio decode ledgers and `EditVerificationEvidence` reuse a video-based `durationToleranceUs`; mapping that object unchanged would allow about one second at 1 fps. Parameterize only relevant audio duration/head/tail checks in the shared synchronous core with the private audio expectation. Editor supplies its existing legacy policy unchanged; Direct supplies these explicit independent facts and limits. Save's converted evidence predicate rechecks the same bounds. Widening AAC tolerance or rewriting Editor behavior is not the solution.

Tests cover actual public S/E wrappers, repeated get/false-queue retry/throw/EOS cases, nonzero S start with E reset to zero, graph silence append or trim despite correct video length, 1 fps video with source audio shorter/longer by hundreds of milliseconds, delayed source audio, missing encoded audio tail, ±120 ms Opus boundary handling without audible loss, valid AAC priming, AAC boundary exactly at/over 42,667 μs, and attempted Opus-plus-AAC allowance stacking. Actual source/MP4 head/tail sound markers and measured timing are required; synthetic counters alone do not establish the unverified source-audible mapping.

### The Opus negative-time question, accurately bounded

The initially noticed audio branch does **not** justify a blanket Opus exclusion. `ExoAssetLoaderAudioRenderer.shouldDropInputBuffer` subtracts `streamStartPositionUs` before testing a negative result. `ExoAssetLoaderBaseRenderer.onStreamChanged` sets that start in renderer time. The official exact-tag `BaseRenderer` documents `startPositionUs` in renderer time and adds `streamOffsetUs` to sample timestamps in `readSource`. Thus raw Matroska time, renderer time, and the composition's local start are not interchangeable. See [Media3 1.11.1 BaseRenderer](https://raw.githubusercontent.com/androidx/media/1.11.1/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/BaseRenderer.java).

The local pinned `MatroskaExtractor` builds Opus CSD, and `DefaultDecoderFactory.createForAudioDecoding` uses `MediaFormatUtil.createMediaFormatFromFormat`, including its CSD buffers. Android documents Opus CSD pre-skip and preroll support in [MediaCodec's codec-specific data contract](https://developer.android.com/reference/android/media/MediaCodec). These facts support testing the ordinary official pipeline first; they do not prove the first audible samples or final padding are correct on emulator-5556.

Remaining risk: the pinned renderer deliberately drops pre-start compressed input, and `DefaultCodec.queueInputBuffer` has no explicit per-buffer supplemental-data handling. That is not proof of audible loss or of correct end trimming. Negative prefix, nonzero codec delay, seek preroll and discard padding need owned fixtures with audible head/tail markers and measured synchronization. Accept normal library handling if those pass; if a specific represented case fails, identify that case and fail unsupported pending a focused fix. Do not silently clip, reset timestamps, forge a successful fixture, or replace Opus with a larger bespoke parser/proof project.

The current official [Transformer supported-formats page](https://developer.android.com/media/media3/transformer/supported-formats) confirms the extractor/decoder/device-encoder dependency model. It is context only; exact 1.11.1 source and device evidence control this implementation.

## 5. A bounded extractor adapter, not a new media parser

Implement one original `BoundedWebmExtractor : MatroskaExtractor` for both owned preflight and Transformer loading. Call the documented superclass hooks for admitted events. Its small responsibilities are resource limits, track/presentation policy and observations.

1. Bind every read/skip/seek to the fixed owned raw extent and operation checkpoint; constrain cumulative IO and valid returned seek positions. Proposed hard caps: 2,000,000 encountered elements/source samples, nesting depth 16, at most two TrackEntries, 64 KiB per codec configuration / 256 KiB total configuration, 1 MiB total retained metadata and 128 bytes for required ASCII identifiers. Count these and sample bytes before allowing unbounded accumulation; source sample observations stream into bounded aggregates rather than a 2,000,000-entry payload list. Require actual fixed-extent end-of-input, a completed track inventory and no uncommitted/partial sample; the special unknown-sized master EOF rule below does not require a nonexistent terminal master callback. Rehash the same raw inode/extent after conversion; mismatch rejects publication.
2. At TrackEntry, capture exact track number/type/codec and bounded fields, reject duplicate IDs or more than one video/one audio, and check content-encoding/encryption before the library can skip a track. At `endTracks`/AssetLoader `onTrackCount/onTrackAdded`, reconcile every admitted entry with actual emitted/selected tracks. Require unencrypted formats (`drmInitData==null`, crypto type none); reject encrypted sample flags/crypto data. Use `DrmSessionManager.DRM_UNSUPPORTED`; no keys, licenses or network resolution.
3. Guard **every binary payload**, including original BINARY, STRING mapped to BINARY, and UNKNOWN mapped to BINARY, with the original-width framing check below before any payload-consuming superclass callback, allocation, read or skip. `super.getElementType` may supply the type classification only; map STRING and UNKNOWN to the protected binary callback so neither the library's string allocation nor its unchecked UNKNOWN skip executes. After the guard, read bounded ASCII identifiers and forward only DocType/CodecID as validated strings to the superclass; skip bounded nonessential names/language metadata without retaining/logging them. UNKNOWN payloads use the adapter's own bounded skip and never `super.binaryElement`. This is identifier/size framing, not codec syntax; no reflection or package-private injection.
4. Constrain master ranges/depth and allowed ignored elements, using callback positions and fixed input length. Reject linked-segment/external/presentation semantics not represented by the profile. Do not claim strict validation of every unknown EBML feature; trusted library tolerance remains explicitly part of the model. If a required bound cannot be enforced with these public/protected hooks, report that concrete gap during implementation review instead of silently declaring it bounded.
5. TrackOutput sample callbacks must handle partial data plus metadata offsets correctly and bound the pending sample buffer. Preflight may count/sample/hash technical transport observations, but **never require source compressed payload equality with AVC/AAC output**. Optional audio supplemental data is interpreted by the admitted library, not a custom Opus parser.

### Preserve the original declared payload length before consumption

Pinned `DefaultEbmlReader` stores the size as `long`, but casts it to `int` for both `binaryElement` and its default UNKNOWN `skipFully`. A positive callback size therefore does not prove the original declared length: for example, `2^32 + 4` arrives as `4`. In the controlled binary callback, take the current `input.getPosition()` as the trusted payload start and use the same owned positional-read capability to inspect at most the preceding 12 bytes within the fixed extent. Enumerate **all syntactic candidates first**: the exact literal callback element ID (one to four bytes) immediately followed by a complete one-to-eight-byte size VINT ending exactly at that payload start. Retain original VINT width and full decoded `long` size. Require exactly one candidate before applying any size, profile or extent filter. Missing/ambiguous candidates reject; never discard an oversized true candidate and then accept a shorter accidental match embedded in its bytes. The look-behind consumes the existing cumulative IO budget, cannot move the extractor cursor, and rejects stale/revoked ownership or out-of-extent reads.

Only after uniqueness, reject reserved unknown sizes for these non-master payloads and validate the complete `long`: checked addition to the payload start, fixed remaining extent, every applicable known-parent end, configured element/configuration/metadata limits, the 4 MiB per-sample limit where applicable, and remaining aggregate work/IO budgets. Require `0 <= declaredSize <= Integer.MAX_VALUE` and exact `declaredSize == callbackInt.toLong()`; no masking, saturation, wrapping or accepting negative callback sizes. Perform these checks **before** `super.binaryElement`, `super.stringElement`, any payload allocation/read, or any skip. Accepted original BINARY then delegates normally; accepted STRING-as-BINARY performs only the bounded identifier/metadata handling above; accepted UNKNOWN-as-BINARY consumes its validated payload through checkpointed bounded skip chunks, never the library's `(int)` UNKNOWN skip. Unknown IDs remain opaque skipped payloads; this mechanism does not discover new masters, traverse their contents or create another demuxer. This closes the declared-size truncation gap only if the actual admitted bytecode passes the three-path matrix in section 11; until then it is a specified implementation obligation, not tested parser safety.

Raw `MediaExtractor` may be used for a capability check, but is not a second authoritative container inventory that overrides the bounded Media3 path. The Android output verifier remains independent.

### Unknown-sized Segment/Cluster on a complete file

Allow the trusted extractor's normal treatment of legal unknown-sized **Segment/Cluster only**, with a fixed owned byte extent and successful HTTP completion. EOF must be the actual end of that extent, all admitted tracks must be inventoried, no pending sample may remain, and normal duration/decode checks still apply. It is not an infinite source and does not require an extra network fetch. Known-sized master overrun, truncated header/payload and incomplete samples remain rejected.

A protected master callback gives a numeric content size without its VINT width. Apply the **same unique-header helper to masters**, including Segment/Cluster: within at most the preceding 12 bytes, enumerate every syntactic candidate consisting of the exact callback ID and **any** complete size VINT ending at `contentPosition`; require exactly one candidate before classifying its size as reserved unknown or known and before extent/profile filtering. Do not search only for all-ones markers. For example, `18 53 80 67 | 01 18 53 80 67 3f ff ff` is a huge known eight-byte Segment length containing a fake Segment ID plus three-byte unknown marker; the multiple-candidate/known-overrun case must reject. Add that exact negative fixture. After uniqueness, only Segment/Cluster may use the reserved unknown encoding; otherwise require full declared size to equal the callback numeric value and checked `contentPosition + declaredSize` inside the fixed extent and applicable known parents. The helper uses the same fixed-extent positional-read capability, cumulative IO budget and stale/revoked checks; it does not parse payloads or codecs. No new EBML reader, upstream source copy or package-private hook is proposed.

Pinned `DefaultEbmlReader` may retain unknown masters in its internal stack, and EOF need not invoke their `endMasterElement`. Maintain a physical outstanding-master callback count matching actual push/pop callbacks, capped at 16; do not pretend a logical sibling reset frees the library's stack. Consequently a file with too many retained consecutive unknown-sized clusters can hit this explicit compatibility/resource limit even if otherwise legal. That is an honest narrow limit, not “all unknown-sized WebM is incomplete.” Required pinned fixtures: unknown Segment + known clusters; a bounded number of consecutive unknown clusters; near/exceeding the physical cap; actual EOF without endMaster; truncated known child; and a known finite size numerically equal to an unknown sentinel but encoded with a wider VINT. The pinned reader also treats an unknown marker as its numeric sentinel when calculating a master end: a short-width marker can therefore trigger `endMasterElement` after that numeric distance, before the legal unknown-master context ends. Such a premature callback is not closure evidence and must not make the file pass. Reject that represented case as unsupported unless a real pinned fixture establishes its valid context boundary; do not fabricate an end callback, clear/reset the internal stack, or call an otherwise legal unknown-size file corrupt merely because this pinned path cannot preserve its context. Test all eight marker widths, both bodies within short numeric sentinels and bodies crossing them, and report the measured supported range. If callback behavior differs, revise the bound from real evidence before admission, not with an alternate parser.

### Same-attempt private input address and fixed-FD IO

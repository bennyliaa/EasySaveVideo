## Findings raised during implementation

1. **Region descriptor persistence (high):** the initial `RecordedSegmentCodec` dropped `CaptureDescriptor.regionCaptureRecipe`, making storage's descriptor-equality admission reject real region captures. The corrected codec serializes the recipe and source geometry in both config and capture records, with separate actual-observation persistence. Positive non-full-region restart tests were added. Corrected source confirmed in the final manifest.
2. **Pause release uncertainty (high):** a failed per-segment native release could be retried in the outer finally block and inadvertently free the native lease. Native ownership now retains a sticky session-level uncertainty flag. EGL target teardown also waits for issued GL work before destroying the surface. Corrected source confirmed in the final manifest.
3. **Atomic session/result publication (high):** committing a catalog result before recording the session's result identity allowed a process-death window to make the same raw group retryable as a new result. Storage now records a pending edit identity before execution and updates the session's published identity inside the same transaction as catalog READY and edit SUCCEEDED. The exact transaction source and host SQL anchors were rechecked in the final manifest. Actual Android crash injection remains NOT_RUN.
4. **Storage native fence (medium):** closed-segment admission originally checked Java writers/readers but omitted the native-writer count. It now requires the complete idle predicate before sealing. The same-session request contract also rejects mixed generations.
5. **Effective versus wall duration (medium):** the original advanced loop used the 30-minute effective-output limit as a wall deadline, including pauses. Corrected source separates the two-hour resource wall limit in both native capture and the runtime watchdog. The UI discloses both limits and the two-GiB total input budget.
6. **Small exact region support (medium):** the legacy 256-pixel requested-profile gate rejected otherwise admitted 128-pixel regions. Corrected source applies the legacy gate only to basic capture; exact region support still requires actual codec admission.
7. **Recovery group reachability (medium):** the initial runtime exposed only the oldest retained session. Corrected runtime/UI provides asynchronous retained-group navigation, checks selection identity before posting, and preserves a published result when its private inputs are cleaned.
8. **Post-capture cancellation liveness (medium):** the initial runtime only armed a main-handler deadline while native capture remained open. Raw hashing, directory sync, SQLite, or editor-storage calls after closure could therefore leave PROCESSING/VERIFYING/CANCELLING indefinitely. Corrected code adds operation-bound processing and cancellation-warning deadlines, including retained cleanup, while preserving ownership until actual completion. A subsequent ordering defect, where the 15-second cleanup deadline replaced the earlier 10-second waiting notice, was also reported and corrected with sticky per-job waiting state and explicit ordering tests.
9. **Typed request snapshot validation (medium):** the first implementation derived input type and validated caller-owned lists before copying them. A mutating list could therefore produce a different stored recipe from the validated recipe. Corrected `EditRequest` takes one bounded snapshot first and validates type, session, generation, uniqueness, count and order only on that immutable snapshot.

The independent runtime/lifecycle review in `RUNTIME_LIFECYCLE_REVIEW.md` additionally covers cancellation versus final publication admission, service-destruction admission, exceptional recovery writes, terminal presentation fallbacks, active-job discard and basic-mode disclosure. Its final status must also be consulted. The publisher now uses a short shared cancel/publication-admission state machine: cancellation wins before admission; after admission the UI reports that the final commit cannot be canceled and awaits its actual result. The admission monitor is not held during filesystem or SQLite work. This reviewer rechecked the shared publisher/token integration in the final manifest.

## Source route examined

- `RegionCaptureContracts.kt` freezes entire display-oriented geometry, inset metadata, even inward absolute crop edges, transform version, and dimension-only evidence. The output rotation is zero; recipe intent and post-consent observations are separate.
- `RecordingConsentController.kt` explicitly requests default-display capture on API 34+, retains only process-memory request correlation, and drains canceled result tombstones before a fresh request. `ProjectionGrantHandoff` is a bounded, single-use in-memory cell.
- `AndroidRecordingSession.kt` contains one `createVirtualDisplay` call. The full-size capture surface feeds `RegionGlCapture`; segmented pause/resume replaces encoder/muxer/file resources while retaining projection, virtual display, OES source, and EGL context.
- `RegionGlCapture.kt` draws a selected texture-coordinate rectangle to an exact-size encoder EGL surface before `eglSwapBuffers`. It does not record the whole display to a temporary file. `RegionTexturePolicy` accepts only full-image axis flips and rejects producer crop, scale, rotation, perspective, and non-finite matrices. Unsupported real devices can therefore fail closed; the supported transform subset is not a device acceptance claim.
- Native video timing uses a following actual encoded sample as the previous sample's endpoint. The unmatched final held sample is not assigned `1/requestedFps`; it is excluded. Configured frame rate remains a candidate for independent verification.
- `RegionFrameAdmission` selects bounded-rate real frames without changing their timestamps. A 60-Hz to 30-fps synthetic positive case preserves the measured clock, while 29-Hz/VFR input remains incompatible with the requested integer-CFR verifier. `MeasuredAudioTail` bounds retained AAC together with pending format samples and the held video endpoint; it writes only whole packets ending at or before the measured video endpoint and discards an unmatched tail.
- `RecordedSegmentFiles` uses journal-derived random filenames, inode identity, exact extent and SHA-256 checks, and rejects symlink/traversal/replacement cases. An unknown identity in the file-create-to-journal gap is retained for recovery rather than guessed or deleted.
- Typed `RecordedSegmentReadRef` is separate from ordinary `MediaReadRef`. The editor request accepts at most 33 ordered, unique, same-session recorded refs, while ordinary requests remain capped at eight. Raw segments have no Save receipt or ordinary catalog representation.
- The widened constructor ceiling for cumulative AAC priming is derived from the unchanged two-AAC-packet allowance per admitted segment, now at most 33 recorded inputs. Ordinary requests still admit only eight inputs; per-packet cadence, all-frame video cadence, exact video count and final video extent checks were not relaxed.
- `RecordedSegmentEditorBridge` independently verifies each closed raw, then uses the existing ordered Media3 editor and full independent final verifier. The latter scans all video timestamps, validates the container tail duration and encoded sample extent, decodes every video frame and continuous AAC PCM through output EOS, and hashes before/after verification. A raw completion callback is not a publication proof.
- The runtime's capture and raw-processing lane remains globally owned through actual native completion. User cancellation and timeouts revoke late results; uncertain native release requires process recovery. The intended entitlement policy allows safe finalization and retry of already-owned raw media without charging again; a new capture still requires a fresh gate and new system consent.

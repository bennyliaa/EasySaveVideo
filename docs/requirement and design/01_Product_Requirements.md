## 2. 产品定位与成功标准

EasySaveVideo 是视频发现、访问、保存和私密管理工具。它对接用户需求与第三方视频内容，不自建互联网全量索引，也不把第三方视频托管到自己的服务器。

核心价值：用户输入关键词或网址，找到并打开原始视频页面，在系统与内容允许的范围内保存为可播放 MP4，随后在自己的媒体库中管理。用户不需要理解 Playlist、Codec 或 MediaProjection，但必须清楚当前使用哪一种保存方式。

```text
[新标签页]
   +-- 输入关键词 ---------------------------------------------+
   |                                                           v
   |  [Provider Framework] -> [VideoDiscoveryCoordinator]
   |       -> [Normalize / Filter / Deduplicate / Rank]
   |       -> [ResultPool] -> [视频网站式分页卡片]
   |                              |
   +-- 地址栏输入 URL ------------+--> [第三方原网页 / Browser]
                                              |
                                          [正常播放]
                                              |
                              [轻量检测 -> 保存 / 录制入口]
                                              |
                       +----------------------+----------------+
                       v                                       v
                    [保存]                                 [独立录制]
                 ① Direct                                  ③ Record
                    | 不适用/可降级                            |
                 ② Stream                                      |
                    | 用户选择+系统授权                         |
                 ③ Record -------------------------------------+
                       |
                [验证 MP4 / 可选编辑]
                       |
             [App MediaLibrary / 免费 Vault]
                       |
              [按用户选择导出相册 / Files / 分享]
```

成功不能定义成“任何网站都能保存”。受保护内容、授权不足、格式不支持、网站改变或平台限制必须得到明确结果，不能无限等待。搜索无结果也必须是可理解的稳定状态。

## 3. 统一术语

| 术语 | 本规格唯一含义 |
|---|---|
| Specification | 平台无关的版本化产品行为、协议、模型和验收标准 |
| Core | 只依赖自身领域模型和接口的业务规则；不是要求 Android/iOS 共用二进制 |
| Provider / VideoSearchProvider | 缩小搜索空间、返回视频页面候选的可替换来源 |
| SiteAdapter | 打开原网页后辅助 MediaDetector 识别当前媒体；不同于 Search Provider |
| VideoSearchResult | 原网页级的发现结果，不能直接当作可下载媒体资源 |
| MediaCandidate | 当前页面检测到的具体媒体候选与可用保存能力 |
| ResultPool | 已验证和去重的有限结果库存；不预下载视频本体 |
| DiscoveryScheduler | 依据生命周期、库存和资源预算决定何时补充 |
| Provider Progress | 每个搜索上下文中各 Provider 的 page/cursor/nextToken 进度 |
| Seen History | 本地功能数据：真实展示、打开、播放、保存等标记；不是诊断日志 |
| ① Direct | 直接获取完整媒体资源；免费 |
| ② Stream | 获取受支持的流媒体分片并生成 MP4 |
| ③ Record | 用户授权后捕获允许的画面与音频，再编码输出 |
| Entitlement / FeatureGate | 平台无关权益 / 功能准入判断 |
| MediaLibrary / Vault | 普通媒体库 / 真正加密且免费的私密保险箱 |
| Recovery Check | 启动及任务恢复时对未完成状态进行有界核验和修复 |

## 5. 浏览器与发现体验

### 5.1 首页与基础浏览

- 新标签页提供地址栏和明确的“搜索视频”输入框。地址与关键词判定可纠正，不把用户输入的网址强制交给付费 Provider。
- 基础浏览支持前进、后退、刷新、停止加载、新建/关闭/切换标签、网页登录、Cookie/Session、JavaScript、全屏视频和可理解的加载错误。
- 普通网页保持简洁；检测到视频存在时显示保存/录制入口。轻量存在检测与用户点击后的完整分析分开。
- 历史、收藏、无痕是完整浏览器需求；不要求 MVP 模仿 Chrome 全部功能。
- 网页内容、标题、缩略图、Provider 响应均视为不可信输入，不能变成系统命令或应用权限。

### 5.2 卡片、分页与结果状态

| 项目 | 行为 |
|---|---|
| 卡片 | 缩略图、标题、来源、可获得的时长；简介/发布日期可选 |
| 元数据缺失 | 显示占位或省略；不得伪造时长、文件大小、清晰度 |
| 点击 | 打开第三方原网页，在 Browser 正常播放 |
| 网格设置 | 每行数量、每页数量可改；建议初始 2 个/行、20 个/页 |
| 页码 | 展示已物化页；Provider 总量未知时不显示虚假尾页或全网总数 |
| 首屏 | 有有效结果即展示，不等待最慢 Provider；不足整页也可显示 |
| 翻页 | 优先消费 ResultPool；库存不足显示“继续查找/稍后重试/更换来源” |
| 排序/筛选 | 来源与重复策略是基础；时长、日期、清晰度等按可得元数据逐步提供 |
| 异步追加 | 不把用户当前阅读卡片挤到其他位置；已显示页稳定 |
| 耗尽 | 明确“当前来源暂无更多”；不循环加载制造无限结果假象 |

### 5.3 Local-first 与资源节制

```text
Provider 缩小互联网搜索空间
             |
       有限候选元数据
             v
设备聚合/过滤/去重 -> ResultPool -> 当前页/下一页
                             ^           |
                             |    未浏览库存减少
                             +-- Scheduler

前台且 Discovery 活跃 -> 低水位补充 -> 达高水位暂停
退后台/退出 Discovery -> 取消请求与预取 -> 保存一致快照
返回前台              -> 恢复结果 -> 必要时补充
```

Local-first 指协调、结果消费和持久化优先在设备上，网络来源仍需要联网，不意味着离线搜索全网。服务器只能是可选 Provider 或 Package 分发服务；不成为启动或保存的前置条件。不得递归无限爬网页，不得预下载搜索结果的视频本体。

前台低功耗持续供给是目标，不承诺来源永不耗尽。“后台异步补充”在本规格中只表示前台 UI 使用期间的异步工作；App 后台必须停止 Discovery，包括新请求、候选扩展和缩略图预加载。已明确发起的保存任务另行管理。

### 5.4 长期记忆与四种重复策略

| 策略 ID | 用户名称 | 行为 | 默认 |
|---|---|---|---|
| `PREFER_NEW` | 优先显示新视频 | 未真实展示优先；不足时补以前展示的视频 | 是 |
| `HIDE_WATCHED` | 隐藏已看过的视频 | `OPENED` 或 `PLAYED` 不再展示；只展示过可再出现 | 否 |
| `HIDE_SHOWN` | 隐藏所有已展示过的视频 | 曾真实进入可见区域的结果不再进入后续结果页 | 否 |
| `SHOW_ALL` | 显示全部视频 | 忽略历史过滤；同一结果集内仍去重 | 否 |

Provider 找到不等于用户看过：`DISCOVERED` 不能自动升级为 `SHOWN`。打开页面不等于播放，网页无法可靠报告播放时保留 `OPENED`，不得假造 `PLAYED`。`SAVED` 是独立事实，不自动伪造已看过。

历史按 SearchProfile 隔离：同一关键词及筛选上下文可续用；全局跨关键词去重属于未来扩展。用户能清除此关键词历史、清除全部发现历史、重置 Provider 进度；这些动作不得删除视频文件。Seen History 是实现用户明确要求的本地功能数据，禁止复制到日志或默认上传。

## 6. Provider 的产品边界

```text
Local Provider ----+
Video Site --------+
Public API --------+--> 可用来源聚合 --> 视频卡片
SearXNG 服务 ------+
可选 Extractor ----+
       |
单个失败 -> 其余继续
全部失败 -> 可选普通网页搜索 -> 地址栏直接访问
                                 |
                         Browser + SaveEngine 独立可用
```

- 支持用户启停、版本查看、检查更新、更新全部和可用版本回滚；完整管理 UI 在 M6。
- 远程控制允许启停、优先级、超时、兼容版本；本地用户禁用优先，远程不能绕过权益或本地安全上限。
- Package v1 完全声明式，不能下载并执行任意 Kotlin、Dex、JavaScript、Lua、WASM 等程序。
- SearXNG 研究搜索广度；NewPipeExtractor 研究视频站深度。能否集成、以何种边界集成由 M0 审计决定。
- 免费基础 Provider 数量维持 0～1 个待商业决策；开发验证必须至少有一个通过审计的真实来源。两者不冲突。
- 无网络或仓库不可用时保留已安装可用包；无需连接服务器才能打开浏览器。

## 7. 保存与录制

### 7.1 保存方法和失败交互

| 方法 | 用户看见 | 执行条件 | 失败后 |
|---|---|---|---|
| ① Direct | “① 直接下载”及进度 | 存在可正常访问的完整资源；免费 | 可降级问题再评估② |
| ② Stream | “② 流媒体保存”及进度 | 受支持流、`STREAM_SAVE` 权益 | 可降级问题才建议③ |
| ③ Record | “③ 录制保存”、实时状态 | `RECORD_SAVE`、用户确认、系统捕获授权 | 安全停止、尽力保留有效产物 |

存在多个视频或清晰度时弹窗选择。大小未知时显示未知或标注估算。Cookie、Referer、User-Agent 等只能在合法 Session 范围传递，不能依靠拿到 URL 就假设无需鉴权。

磁盘满、用户取消、明确 DRM/受保护内容等不应盲目继续下一方式。缺少权益进入可取消的功能说明，不自动购买。③永不偷偷启动。用户可以直接选择独立录制入口，不必人为制造①②失败。

所有成功结果必须是验证通过的可播放 MP4；原资源为 WebM/MOV 不得仅改扩展名。必要的兼容转换属于基础输出流程，不以“高级压缩”名义阻挡免费①；无法合理转换时明确失败/提供可用替代，不声称已保存。

### 7.2 Recorder 演进

```text
M4 内部 MVP
系统授权 -> 整屏录制 -> 开始/停止 -> MP4 验证 -> 基础预览
     |
     v
M5 高级录制（原先讨论的 MVP 1.1 方向）
框选/全屏 -> 开始 -> 暂停 -> 继续 -> 多段 -> 自动拼接
     -> 二次画面裁剪 -> 预览 -> 可选压缩 -> 保存
     |
     v
后续实验
记住站点选区 / 独立播放捕获 / 高级导出
```

本次重建按最新范围将高级暂停/继续与片段编排排入 M5；M4 若底层已支持可以提前验证，但不改变商品边界。录制是独立模块，SaveEngine 的③复用它。

- 暂停期间用户可继续观看，但该时间不得进入最终视频；计时显示有效录制总长度。
- 多段最终自动拼成一个文件；异常时允许保留可恢复片段，但不能把零散片段冒充成功成片。
- 框选支持拖动、四边/四角缩放、全屏、重置、确认和取消；可先完整捕获再裁切，但必须如实说明临时数据范围。
- 停止后可预览并二次裁切画面上下左右；压缩至少提供原质量和节省空间，不强制重复转码。
- 优先内部音频，仅在系统与来源允许时使用；无法获取明确提示，不能偷偷切换麦克风。麦克风未来单独选择且默认关闭。
- 录制 A、切换 B 后仍只录 A 是有界技术实验，不是 MVP 承诺。普通整屏录制会捕获当前可见内容，切换前应提示影响。

### 7.3 保存任务与后台

任务中心展示分析、当前方法、进行中、等待用户、暂停/中断、处理、完成、失败、取消。进度未知不得伪造百分比。①②尽可能在标签切换和系统允许的后台状态继续；后台保存不是 MVP 一票否决条件，但前台必须稳定，后台限制必须可见。

③按独立系统授权与录制生命周期管理；不能通过统一 `onStop -> cancelEverything` 把三种任务混在一起，也不能因此放开后台 Discovery。

## 8. MediaLibrary 与免费 Vault

```text
Direct / Stream / Recorder / Editor
                 |
          验证后的媒体产物
                 v
       [MediaLibrary 元数据 + 文件]
          |                    |
    普通文件夹             [Vault 加密对象]
          |               解锁后受控播放
          +---------+----------+
                    |
            用户明确导出 / 分享
                    v
             相册 / Files / 接收 App
```

| 范围 | 必须支持 |
|---|---|
| 普通媒体库 | 缩略图、名称、时长、大小、分辨率、时间、播放、重命名、移动、删除、自建文件夹 |
| 默认目的地 | App 媒体库为初始默认；支持私密空间、相册、每次询问等设置 |
| 外部文件夹 | 用户通过系统选择授权；授权失效时保留内部产物并提示重新选择 |
| 导出与分享 | 按需导出相册、Files 和系统分享；禁止静默发布或上传 |
| Vault 认证 | PIN 或密码、生物识别、失败重试节制、自动锁定 |
| Vault 存储 | 真正加密，Keystore 管理关键密钥，敏感索引/缩略图同样保护 |
| Vault 隐私 | 最近任务遮罩、锁定时关闭私密画面、明文临时文件受控清理 |
| 费用 | MediaLibrary、Vault、认证、加密、自动锁全部免费 |

自动锁支持立即、1/5/15 分钟和重新启动后等设置；产品初始默认建议立即锁定。选择宽松自动锁不代表允许最近任务泄漏。导出私密媒体前说明目标是普通文件，已被用户导出的副本不受 Vault 控制。密码丢失、Keystore 失效和卸载后的可恢复性必须在 M6 明确，不能承诺万能找回。

## 10. 设置、隐私与可靠性

| 设置类别 | 内容 |
|---|---|
| 发现 | Provider 启停、重复策略、省电/平衡/积极模式、每行/每页数量、筛选与历史清理 |
| 保存 | 每次选择清晰度、默认目的地、Wi-Fi only、并发任务数 |
| 录制/编辑 | 音频状态、默认压缩模式、预览、选区控制 |
| 媒体/Vault | 文件夹管理、自动锁、生物识别、导出、密钥异常说明 |
| 隐私/诊断 | 缓存/历史/临时文件清理、用户主动导出错误日志 |

Release 只记录必要 ERROR 技术日志，不记录普通业务过程、关键词、浏览历史、视频内容、Provider 结果、Cookie、Token、PIN、密码、密钥或私密媒体。日志必须轮转、限额、过期清理，默认不上传。正常进度更新是 UI/功能状态，不得借故变成行为日志。

所有模块遵循 Fault Isolation + Self Recovery + Graceful Degradation。每个异步操作有 timeout、cancel、bounded retry、terminal state；Provider、WebView、Save、Recorder、Encoder 分别隔离。用户始终有可操作的稳定页面。原子更新与 Recovery Check 详见 02/04。

## 11. 保留需求与明确未承诺事项

| 类别 | 范围 |
|---|---|
| 保留到后续 | Automation、TaskQueue 自动调用、站点选区记忆、高级导出、iOS 原生实现 |
| 技术实验 | 隐藏 A/浏览 B 仍录 A、复杂格式、跨设备/平台能力差异 |
| 不纳入当前实现 | 自建全网爬虫、强制账号、云同步、广告、社交、视频服务器、复杂推荐 |
| 不允许 | DRM 绕过、模拟系统录屏授权、远程任意可执行代码、无限搜索/重试 |
| 不作承诺 | 所有网站兼容、无限结果、所有后台任务必定继续、所有音频均可录制 |

需求调整必须先更新 Specification 和 Decision Log，再改平台实现。任何缩减免费能力、删除高级需求、提高 minSdk 或让 Provider 成为硬依赖，都必须作为正式决策变更，不能以修 Build 为理由悄悄修改。

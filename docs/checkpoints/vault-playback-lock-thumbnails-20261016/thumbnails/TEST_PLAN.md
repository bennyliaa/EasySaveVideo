# Required verification before calling the slice connected

All cases below are planned, not executed in this design task. Cloud fixtures must be deterministic public synthetic bytes/fake ports. Preserve existing tests rather than weakening assertions for new source shapes.

## JVM / source-contract cases

1. **Same-owner admission:** exact revealed object/generation/catalog + current readLease/root/auth/presentation epoch/host token accepted; foreign owner, forged fields, stale catalog, stale host, unknown cleanup, absent route/foreground, playback/media/recovery/credential work all rejected before file/native acquisition. A generic thumbnail key cannot authorize reads.
2. **Connected completion:** a visible request passes the actual BoundedThumbnailSession → existing Vault read reservation → existing store/auth reader → shared decoder seam → actual reader/file drain → protected Host frame path. THUMBNAIL creates zero player/surface/audio/network instances and no playback-status UI. Confirm no deadlock or synchronous wait across native/Main/Vault work lanes. Duplicate/late/reentrant completion cannot release a newer request or double-close a transferred frame; callback rejection/exception retains ownership and the original process gate until actual retirement.
3. **Transport semantics:** authenticated size; random seeks; short reads; size requests above 64 KiB; zero length; exact and beyond EOF; negative/overflow arguments; truncated/no-progress reads; final-segment failure; wrong operation lineage; invalid destination ranges. Revocation/corruption/budget errors never become successful EOF and never publish extra destination bytes. Read/getSize callbacks accounted across callback threads.
4. **Budgets:** 16 visible identities/frames maximum, queue overflow, one native owner, reserve result bytes before decode, aggregate old-host/session/Main handoffs, cross-domain ordinary/Vault lane exclusion, max 8 MiB returned plaintext/512 callbacks/3-second authority lifetime. Queued pre-native viewport cancellation/busy rejection consumes no attempt and can rejoin; native-start/failure/cancellation/UNKNOWN cannot be reset by scroll/stop/start. Preparation/auth failure remains terminal for this reveal. Max 297 bounded attempted/terminal exact refs per authenticated reveal; no retry UI. Platform oversized Bitmap/null/config mismatch is rejected and owned cleanup is observed.
5. **Every race boundary:** cancel/lock/route exit/background/device lock/capture loss/host detachment during file acquisition, reader acquisition, final authentication, source setup, each read, native decode, native release, before Main post, after post but before delivery, during draw and during root cover acknowledgement. Late callbacks cannot publish/revive; no new native task before real release.
6. **Failure and independent drain:** MMR constructor/setDataSource/decode/release throws or blocks; source-close callback arrives early/late/twice; read hangs; reader/file close throws; executor rejects/executes-then-throws; Main post rejected/ambiguous; frame close fails; old host still attached. Unknown native does not prevent safe drained reader/file retirement, but overall Vault cleanup/new admission stays blocked. Never speculative second close after ambiguous failure.
7. **Frame/host lifetime:** stale post-close draw produces no image; no Bitmap escapes; exact display token check each draw; successfully handed-off frame survives read-reservation retirement but not presentation revocation. Exact observed root-cover/detach plus frame close (not Compose disposal alone) removes visibility obligations before aggregate host/cover acknowledgement, avoiding a circular wait. Healthy offscreen close releases app-owned bitmap bytes but keeps a bounded no-pixels retirement marker; failed close retains frame/budget. No GPU-erasure claim in state or reports. A new Activity cannot erase old UNKNOWN accounting.
8. **Viewport/UI wiring:** real lazy-list visible keys only, no composed/precomposed offscreen loading, stable 16-item truncation, stop/offscreen cancellation, lock control always usable, thumbnail busy state does not freeze unrelated view controls, selected export/playback asks existing retirement path. Late work never restores private name/image/semantics after cover. Generic localized placeholder/semantics only; no name-to-string/log/SavedState/path/URI fallback.
9. **Ordinary regression:** existing bounded-session, native gate/resource/read/ownership tests; original source retirement and ordinary library thumbnails; ordinary process-gate restart behavior; SourceMove/recording collision checks. Generic key/async seam cannot accidentally route private frames into ordinary retainedSessions/currentSession/retireExactSource.
10. **Vault regression:** playback runtime/transport/platform retirement and hostile executor tests, protected host/input/modal/surface guards, recovery/move/export/batch/auto-lock policy and settings admission, free-offline/store-failure contracts. Preserve final20 source evidence, 95-artifact equality and notices, no dependency/permission/manifest/crypto-format changes.

Central build owner should run focused new tests plus affected library/Vault/Host suites, then the same full build/lint scope as the baseline. Record suites/tests/pass/skip separately and verify final-source hashes after any compatibility edit. Nothing in the baseline's 6,475 PASS + 2 SKIP is evidence for newly implemented thumbnail behavior.

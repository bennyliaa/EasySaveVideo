# Compiled source admission and local verification configuration

This checkpoint adds a neutral VerificationSourcePolicy interface and a finite CompiledVerificationSources catalogue. Only trusted compiled application code can provide catalogue origins. Session configuration selects existing policy IDs with acknowledgement; it cannot add URLs, dynamic rules, search-result domains or redirect targets. The application composition root currently injects an empty catalogue. Thus production remains UNCONFIGURED and no new source has been enabled. Third engines use the same constrained request, not a separate broader fallback path.

VerificationOriginPolicy performs no DNS or I/O: HTTPS only, exact IDN/ASCII normalized host and port, no userinfo/fragment/encoded authority/IP literal/local host, no wildcard/subdomain matching. Compiled origin entries cannot carry a path/query. Explicit nondefault ports require an exact compiled entry. DNS address admission remains in B's transport, now using a shared address-bytes policy rejecting private/loopback/link/multicast/carrier NAT and benchmark ranges; only globally routed IPv6 unicast is accepted. Every resolved address is checked before selecting one pinned address; cookies, proxies, redirects, connection retries and downloads remain disabled. Redirects are refused, not followed; any future independently requested target must pass admission again.

Application VerificationConfiguration carries the immutable selected catalogue IDs/origins in process memory only. configureLocalSources checks the current revision/generation, acknowledgement, known IDs and catalogue limits before the existing change notification fences owners. Remote enable/disable preserves local selection; a failed change clears authority. Dynamic consent is not newly granted by source selection. Existing UI controls now show the catalogue and status and can apply a selection only if the build contains an approved entry. With today's empty production catalogue, there are no selectable production sources. Pending cards expose UNCONFIGURED / UNSUPPORTED / DENIED / READY independently of verification outcome; readiness is admission, not confirmation or a promise of fallback success.

VerificationEngineRegistration supplies the selection's network constraints to the shared scheduler. A production sourceAdmissionRequired request is denied before invoking any engine when the exact origin is absent, TLS is disabled or redirects are permitted. This gate applies before A/B/third-engine selection: an unadmitted candidate cannot reach a broader fallback. Existing explicitly owned fixture-only engine injection remains test code; it is not exposed as a production HTTP configuration or policy ID. Low-level legacy/fixture EngineRequest calls retain their existing constraints contract; the application composition root supplies the mandatory production gate.

Existing B controlled-loopback tests cover refusals/429/redirects/body budgets, cancellation, close and dynamic consent; both frozen original corpus tests are supplied their original100+80 files, not skipped/recreated.

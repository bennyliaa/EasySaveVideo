## 1. 开工交接

交给Coder：本目录九份Markdown与效果PPT，原ESV规格、SkinKit资料和正式源码位置。Coder阅读后提交基线/复用/接入台账，不要求重新做整套产品设计。

## 4. 分层验收

| 验收层 | 判断内容 | 通过不代表 |
|---|---|---|
| UI框架 | 全部目的地、窗口、组件、状态、主题/语言 | 真实保存/录制成功 |
| 模拟交互 | 固定场景、防重、空错恢复、可见标识、无副作用 | 真授权、加密或支付完成 |
| 已接真实业务 | 真实接口、权限、任务、文件、认证、安全与回归 | 其他仍模拟的能力完成 |
| 视觉比对 | 同条件截图、结构/Token/长文本、差异接受 | PPT所有概念像素可直接成为dp |
| 发行 | Release隔离、精确依赖准入、许可、构建/兼容 | 已完成市场发布或商店认证 |

允许在业务尚未完成时签收“UI框架+明确模拟范围”，但需列未完成真实能力及其原功能里程碑。不得用“UI完成”冲抵原规格Vault、MP4、恢复等功能Gate。

## 5. 效果图比对方法

1. 将第07矩阵每行映射到实际页面/状态/场景。
2. 固定设备窗口dp、主题、语言、字号、场景与版本；截图去除效果图展示边框，保留真实系统Insets作为说明。
3. 先比结构与主操作，再比组件Token、密度、排版、状态和语义。
4. 有意差异标注位置、原因与影响，附实际图，不只写“系统不同”。
5. 冻结实际Token/布局后建立真实UI Golden，后续变更按真实Golden回归。

首版概念参考不要求媒体照片/时间/系统授权像素相同；未知字段、四策略、导航数量、商品边界与安全提示必须正确。允许换行和响应式收栏，不允许因此隐藏主操作。

## 6. 通过条件

- UI-A～E退出条件具备证据，P0/P1清零。
- 第07矩阵全部有实现/截图/测试/差异状态；文档页也能找到对应规范落实证据。
- 默认Light/Dark、System与首期语言、手机/平板、200%字号可用。
- 已有可调用功能真实接入，未开发位置完整且模拟标识清楚，无伪造成功。
- 主题/语言/窗口变化不重复保存/录制/购买，不丢现有任务，发现后台边界不回退。
- Vault真实安全检查通过或明确未开发，不把模拟安全视为PASS。
- Release无任意Fake购买/解锁，依赖与许可准入完成，原功能回归执行。
- 后续API31决定及替代旧API30关系可查，最低API31实际兼容验证完成；不能据本包宣称API30兼容。

## 7. 不接受的交付

只有APK无源码/版本；只有理想截图无交互；使用整页PPT图片；页面看似真实却全部Fake；真实失败后显示模拟完成；复制SkinKit或新建第二套主题/导航/任务框架；关键文案硬编码；私密数据进入普通缓存/截图；只在一种窗口或一种语言验证；宣称未运行测试通过。

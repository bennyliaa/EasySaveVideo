## 1. 实施前提

先阅读索引中的ESV规格、正式源码AGENTS及SkinKit资料。本文不授权重置源码、替换已稳定领域实现、放宽依赖准入或改变最低系统。两快照AGENTS记录后续决定为API31，优先于原规格API30；在正式仓库确认同一记录。工作以小批可追踪提交交付。

当前快照可作为定位线索：已有`ui-theme`、`EsvComposeTheme.kt`、发现/保存/录制/编辑/库入口。Coder必须核对实际代码，不将本包中的示意接口名直接当作已存在类名。

## 3. Theme与DesignSystem落地

1. 沿用`EsvTheme`的正式Token Registry与`readSnapshot`职责。增补前检查同名Token类型，不能在另一模块重复注册成不同类型。
2. 将当前视觉快照集中映射为ColorScheme、Typography、Shapes及ESV组件额外样式。Material3的正常控件可用标准实现；状态色/文字/焦点/禁用与SkinKit不一致时在公共组件中显式映射，不能让平台默认值绕过主题。
3. `EsvText/EsvButton`等公共入口可保留兼容签名，逐步以标准组件承载交互；避免同页形成两个视觉体系。既有Foundation桥接的pin、Subscription与状态优先级语义必须保留。
4. 公共视觉字面量只允许在正式默认主题数据、安全适配或已说明的业务几何算法中；Feature不得自行定义颜色、字体、圆角和阴影。布局关系、比例和48dp安全下限不属于皮肤可任意重排的内容。
5. Light/Dark与跟随系统可切换，持久化选择，不持久化ThemeReadView。invalid包或缺资源按正式候选链回退，必须有诊断但不写用户敏感资源地址。
6. 当前Kit若未提供某Compose资源处理能力，应在ESV适配层补租约/解码/绘制接缝；不得宣称SDK自带Compose实现。未选择个人照片、动画、商店等可选模块不因效果图而强行接入。
7. 海景作为页面装饰候选时需归档可分发资产及许可，并经主题drawable/宿主文字保护实现；不能裁出概念图的海景与文字作为一个背景图。资产未就绪先用主题纯色，不影响业务开发。

## 4. 状态、导航与生命周期

业务状态用不可变UiState、Flow和ViewModel，瞬态显示状态按最小必要层级提升。ViewModel不得持有Activity、View、WebView、系统授权Intent或Projection。真实任务持久化在现有任务层，SavedState只记录ID与轻量显示状态。

将现有页面布尔切换迁移为官方导航目的地及显式弹层状态，先保留适配路径，再移除被替代入口；不可同时保留两套正式返回栈。WebView对象归Browser Host，同一个标签ID在分栏变化时不得重复创建Session。无法跨Activity保留原实例时按宿主已有恢复机制重建并重新关联标签，不承诺同一View永存。

主题与语言变化只使UI重新映射，不创建第二个Coordinator。发现活跃条件由一个入口组合：App前台、发现目的地实际可见、允许预取状态。Compose收集停止不等于领域发现已取消，必须显式通知既有调度门。后台立即禁止新发现请求，2秒内取消在途工作按原规格验证。

稳定媒体ID、任务ID、标签ID为Lazy列表Key。可见性事件使用去重/曝光策略而不是在Composable正文写Seen；事件归约不得因重组生成新的命令ID。

## 5. 真实/模拟接入

逐动作登记`REAL/DEMO/UNAVAILABLE`，混合页面使用每项状态标记。Mock数据与真实业务使用同一UiPort和页面模型，模拟实现禁止调用真实网络、商店、文件输出、Keystore或MediaProjection。

Internal构建可以提供确定性场景切换器；Release不得包含任意Fake授权、购买成功、假解锁或越权录制入口。未开发功能按发行策略隐藏、禁用说明或显示“即将提供”，不能伪装正常可用。

同一动作配置为REAL后，其超时/错误只能产生真实错误或等待，不能回退DEMO。不能把Fake输出插入真实媒体库。模拟进度必须由固定场景时间轴驱动并标识，真实进度只能来自领域事件。

## 6. 图片、播放与私密

先复用已有缩略图/媒体Reader；公共网络静态图采用已准入成熟加载器。Feature传PreviewRef，不直接取Cookie、Uri或解密文件。Web缩略图、普通媒体与Vault三个安全域分别定义缓存键、生命周期与访问边界。

Vault锁定/会话撤销后取消请求、清除内存图与语义标题、关闭私密播放。禁止将解密内容交给普通磁盘缓存；不使用全局共享URL Key缓存私密缩略图。需要临时明文时沿用已审查的私有目录、租约、撤销、启动清理协议，不由页面另建流程。

播放器、导出、编辑沿用现有媒体组件。无真实播放能力时展示明确不可用或公开演示素材，不用假的播放进度充当真验收。大图解码按显示尺寸、可见区域与预算，离屏取消；不在主线程解析媒体或解码主题资源。

## 7. 国际化实施清单

- 资源键按功能和语义命名；中文/英文键集合一致；不可翻译的ID单独声明。
- Date/Number/Duration/FileSize显示集中格式化；不用字符串拼接翻译句子。
- 消息模型使用资源键/错误码与参数，领域错误不直接展示stack trace或原异常。
- 语言入口为System/简体中文/English首期建议；跟随系统不等于写死为中文。
- 平台locale与旧系统兼容路径使用唯一所有者，按当前Activity及依赖基线选择；语言切换事件不重建任务层。
- 语言资源、主题资源与数据内容分离，切换不重跑网络搜索或重新提交保存。
- 内容描述、空图标签、通知、对话框、模拟标识、系统交互前说明都需翻译。
- RTL使用start/end、正确镜像导航；播放时间、文件名/网址按实际方向保护。RTL发行清单另行冻结，但伪本地化需发现硬编码方向。

## 8. 异常与命令

取消是明确业务命令，关闭Sheet不是隐式取消全任务。重复点击提交使用同一命令/幂等键；已接受后禁用再次提交并可对账。需要用户动作的结果进入可恢复状态，不靠一次Snackbar保存关键状态。

③录制的用户确认与系统授权分两步，系统请求ID与当前前台实例绑定。过期回调、页面关闭、取消、进程死亡均不能自动再提交授权。收到系统停止优先归约，不重复释放底层资源。

安全错误按原规格：DRM不绕过，满盘不自动转录屏，认证过期回原站重新登录，权益缺失不是可自动重试网络错误。可恢复动作仅在能力明确时显示。

## 9. 验证与提交

每批改动运行必要单元/适配/语义测试、相关Android检查及现有依赖准入任务，最终按权限范围提供Release构建验证。使用项目现有测试命令；文档不编造不存在的Gradle任务。真机验证Projection、音频、编码和实际文件，模拟器或单元测试不能替代。正式仓库若保留“APK/AAB装配、设备安装须另行授权”的约束，本包不覆盖它；先完成已允许编译/lint/JVM/ABI检查，未授权设备步骤记NOT_RUN并按项目现行流程安排，不伪造证据。

按UI-A～E提交：先主题/资源、再Shell、再每个垂直流程、最后测试与视觉证据。每次说明变更范围、真实/模拟接入、依赖差异、已执行验证和遗留问题；不得提交Cookie、凭证、用户媒体、私密截图或完整响应。

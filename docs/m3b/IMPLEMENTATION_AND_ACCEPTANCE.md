# M3-B: bounded static HLS development slice

Status: verified **restricted development checkpoint**; not general Stream acceptance, full M3 acceptance or a distributable release. M3-A base: `87d45ffc94e949ad0c15d0b9989d2d730287fb82`. An explicitly unreviewed recovery checkpoint is `ee4e398e35f5051088f1fd5df6aefff98750af1f`; final review fixes follow it.

## User and architecture boundaries

- Browser/Direct remain free and independent of Providers. Record is unavailable. Release has no fake entitlement source or purchasing path; its unavailable store source cannot grant Stream. Debug alone can exercise entitlement combinations.
- Native Save detects bounded current-page candidates. HLS requires a separate explicit, entitlement-gated check. Master variants are displayed for an explicit fixed choice. A media playlist is also explicitly confirmed. No auto quality choice, adaptation, alternative URL fallback, or automatic save is added.
- Preparation holds signed URLs, response bases and manifest bodies only in memory. Its original two-hour deadline, bounded manifest planning budget and consumed network bytes are retained through selection. The UI expires in at most 60 seconds and does not renew the deadline. Dismissal/navigation/background cancels only the preparation it still owns.
- Selecting a variant reserves the sole execution lane through command submission. UI and command-entry gates are independent. A stale dialog or prior preflight callback cannot cancel a newer preparation or an accepted task. Entitlement snapshots are synchronized across UI/control threads.
- On accepted submission, preparation bytes are recorded exactly once in the private task journal. Retry bytes consume the same lifetime allowance. The journal holds origin plus source digest, not paths, queries, cookies, headers, manifests or downloadable segment URLs.
- Immediate memory-only background and user-cancel signals do not depend on the bounded control queue. Durable state updates remain off the main thread. Accepted tasks pause through coordinator-owned cancellation. Interrupted/incomplete Stream requires source reselection and a new task; no resumable fragment checkpoint is claimed. A completed local MP4 can be reverified from its durable output constraints.

## Guarded media path

1. Original strict JVM HLS parser accepts only static VOD and a single exact media selection. It rejects encryption/KEY, MAP/fMP4, live/event, independent audio/subtitles, byte ranges, discontinuities, unknown unsupported tags, nested masters and incompatible declarations. Declarations alone never establish real codecs.
2. Dedicated system HTTPS fetcher retains normal TLS/hostname validation, public-peer checks, manual checked redirects, strict response/body length/encoding checks, no Range, no automatic retries and no global CookieHandler. Every received body byte is charged, including failed attempts. Only the exact initial manifest may receive its short-lived same-origin credential lease; variants, segments and redirects receive no credentials.
3. Ordered TS objects are stored only under a journal-owned random artifact namespace in no-backup private storage. Each segment has bounded bytes, fsync and SHA-256 evidence. A full output-size reservation is retained while downloading. No original remote manifest is written to disk.
4. Official pinned Media3 1.11.1 `TsExtractor` is the demuxer. An original bounded packet/profile checker adds fail-closed structural checks where the general extractor is intentionally tolerant. It does not implement an alternative media demux/remux engine. Actual SPS/PPS, ADTS, program/track, continuity, timing and format observations must match the narrow profile. All inputs are checked owned files opened without following symbolic links.
5. The engine constructs a finite local-only playlist with generated IDs. Its custom DataSource accepts only those exact registered IDs and byte intervals, with no default filesystem/network fallback. Media3 HLS is given this factory, zero internal retry policy and an explicit unsupported DRM manager. No DRM/license fetch path, optional codec extension, remote URI or arbitrary local file reaches the engine.
6. Transformer receives only encoded samples. Both decoder and encoder factories reject any request; there is no implicit transcode. Actual output tracks, sample counts, sample boundaries, flags, relative timestamps, payload bytes/digests and AV origin offset are checked against preflight evidence. Muxer metadata cannot copy remote media metadata. Output seeks, writes and truncations are byte-bounded through the admitted MP4 muxer.
7. Success requires the owned local readers, muxer and tracked Transformer/ExoPlayer/HLS loader threads to actually release. A timeout is not release evidence. Uncertain or abandoned work retains its lane and workspace; late results cannot become success. Release uncertainty is checked again by the coordinator after transfer, after final verification and before the terminal publish CAS.
8. The real output is atomically adopted into the existing owned MP4 staging slot, then passed through the original independent Android MP4/container/track/video-decoding verifier and durable commit protocol. Stream adds actual duration/track/dimension expectations, plus full audio decoding that rejects decoder rate/channel expansion or changes. Native audio decoding remains inside the same bounded 60-second verification lane. Cache bytes, TS concatenation or an `.mp4` suffix never establish success.
9. Save record wire format v2 adds technical Stream output expectations and reads prior v1 Direct records, including completed transfer/verification/receipt records. A stored method/expectation mismatch fails closed on construction and on the recovery path.

## Deliberately narrow profile and engineering limits

These are development safety bounds, not measured product promises:

- Static HTTPS MPEG-TS, 188-byte packets, one program, one stable progressive AVC Baseline video track, zero or one multiplexed AAC-LC-declared track. Expected audio is a lower bound: unknown page audio does not authorize dropping a real track.
- Every segment must repeat PAT/PMT and SPS/PPS and begin with IDR. Each PES contains exactly one AUD-delimited, single-slice I/P access unit. A segment-final unbounded PES requires EOS; the final segment must already contain an extra empty AUD followed by EOS. ESV does not synthesize or repair those bytes. Most ordinary TS-HLS lacking that unusual terminal structure is intentionally unsupported. The pinned reader's actual final-AUD behavior is tested with original synthetic bytes; nominal source comments are not treated as observed runtime behavior.
- No B-frames, encryption, unknown programs/tracks, changing SPS/PPS/audio format, transport loss, discontinuities, separate renditions or fMP4. Strict media that fails these rules is rejected even if a general player could display it.
- 2 GiB total input/artifact ceiling, 4 GiB lifetime network bytes, at most 128 MiB per segment, and a 2 GiB output-space reservation. Scratch and output coexist temporarily; same-filesystem adoption avoids a second final-output copy.
- 2 MiB per manifest / 8 MiB cumulative manifest bytes, 8 parsed manifests, 64 variants, 10,000 segments and at most 24 hours declared duration.
- Engine additionally limits each segment to 60 seconds, each sample/PES to 4 MiB and each track to 250,000 samples. Video dimensions are at most 4096 per axis and 8,847,360 pixels; audio has one or two channels and 8–96 kHz. Timing tolerances are intentionally narrow and documented in the code/tests.
- No progress for 30 seconds fails network/export; connect timeout is 10 seconds; at most five redirects. Final verification is at most 60 seconds. A long audio track may exceed full-decoding verification time and fail closed.
- M3-A task retention/recovery limits remain unchanged. There is no background service, WorkManager or wake lock.
